# Form Layouts

How the kit's fields are arranged into a form: sections with a heading
and a line of context, fields one or two to a row, and a row of actions
at the end. Four pieces: `FormSection`, `FormFieldGroup`,
`FormFullWidth` and `FormActions`. The `<form>` element is yours.
After Tailwind UI's Form Layouts.

```sh
npx shadcn@latest add https://ontheshore.biz/zweihander/r/form-layouts.json
```

## Field groups

Related fields inside one section, under a legend: an address, a set of
checkboxes. `FormFieldGroup` is a `<fieldset>`: it takes the section's
whole row, lays out its own columns, and `disabled` turns off every field
in it, Checkbox, Switch and Radio included (they are left out of the
submitted data, as the browser does for any disabled field). Disable a
group while it does not apply, with the reason on screen, as the "Ship to
the billing address" checkbox does here; see
[Field › Disabled](?path=/docs/components-inputs-field--docs) for when to
disable, hide or make read-only.

## FormSection props

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `title` | node | – | Required. An `h2` by default. |
| `description` | node | – | |
| `children` | node | – | The fields. Give each input `isFullWidth`. |
| `layout` | `split`, `stacked` | `split` | Split puts the intro in a column beside the fields. |
| `columns` | `1`, `2` | `1` | Two fields to a row. Wrap one in `FormFullWidth` to span the row. |
| `isCard` | boolean | `false` | |
| `footer` | node | – | Usually `FormActions`; the card's bottom band when `isCard`. |
| `headingLevel` | `2`, `3` | `2` | |

`FormFieldGroup` takes `legend` (required), `description`, `columns`
(`1`, `2`) and everything a `<fieldset>` takes, `disabled` among them.

`FormActions` is a row of buttons aligned to the end: secondary actions
first, the primary one last.

## Layout

- **Sections respond to their own width.** Split turns into stacked under
  48rem of section width, and two columns into one when the fields' side
  of the section (its whole width once stacked) is under 32rem. A form in
  a sidebar or a phone needs no extra props.
- **Sections are size containers**, so they take their width from where
  they sit. As a flex or grid item that would shrink to fit, give the
  section a width (`inline-size: 100%`), or it collapses.

  <Canvas of={FormLayoutsStories.Narrow} />

- **A field group takes a whole row** of a two-column section, and its
  own `columns` follow the same 32rem rule.
- Labels sit above their fields, never beside them: the label width does
  not depend on the longest translation, and a form reflows to a phone
  with no change.
- Actions end-aligned, primary last: the same place in every form, where
  the eye and the Tab key end up.

## Accessibility

- Each section is a `<section>` with a heading, so the form's parts are in
  the page outline and a screen reader can jump between them.
- Group related fields in a `FormFieldGroup`, as the Notifications and
  Billing sections do: a `group` named by its legend and described by its
  description, so a screen reader announces both on entering it.
  RadioGroup is a group of its own; do not wrap it.
- Mark required fields with `required`. The field shows the asterisk and
  the browser enforces it; say in the description if most fields are
  optional instead.
- Never disable the submit button to show that a form is incomplete. Let
  it submit, and show what is missing next to each field.
