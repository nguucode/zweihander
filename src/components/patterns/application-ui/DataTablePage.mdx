# Data Table Page

A list screen: search and filters above a [Table](?path=/docs/components-data-display-table--docs),
what is shown and the pages below it, and, while rows are selected, what
you can do with them. Two pieces, `TableToolbar` (with
`TableToolbarGroup`) and `TableFooter`, around the kit's Table, Search,
Select and Pagination. Filtering, paging and the data are yours: the
stories show one way to wire them.

```sh
npx shadcn@latest add https://ontheshore.biz/zweihander/r/data-table-page.json
```

## Props

**TableToolbar**

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `children` | node | – | Search, filters, the primary action. |
| `selectedCount` | number | `0` | From 1, the selection bar replaces the children. |
| `selectionActions` | node | – | |
| `onClearSelection` | function | – | Shows "Clear selection". |
| `selectionLabel` | `(n) => string` | `"{n} selected"` | |

`TableToolbarGroup` wraps the part that should take the free space and
wrap first, usually the search and filters.

**TableFooter** takes `summary` ("Showing 1–5 of 12") and, as children,
usually a Pagination.

## Behaviour to copy

- **Filtering returns to page 1.** A new query on page 3 would otherwise
  show an empty page, or a page the reader never asked for.
- **Selection is by id**, so it survives sorting and paging (Table's
  `getRowId`), and an action clears it once it has been applied.

## Layout

- No breakpoints: both bars are flex rows that wrap, so they adapt to the
  width of their container, not the viewport.
- `TableToolbarGroup` grows from 16rem and wraps first. On a phone the
  search takes its own line and the filters and the primary action flow
  under it, instead of anything shrinking below use.
- In selection mode the actions are pushed to the end of the bar and drop
  under the count when they no longer fit.
- The footer puts the summary at the start and the pagination at the end;
  when both do not fit, the pagination wraps under the summary.

## Accessibility

- The selection count is a polite status line that is always in the page,
  so "2 selected" is announced as it changes, and silence when it clears.
- Search and the status filter are named ("Search projects", "Status")
  without visible labels, since the table's caption and placeholder make
  their purpose clear on screen.
- The empty state is a heading inside the table's body, so a screen reader
  reaching the table hears why it is empty.
