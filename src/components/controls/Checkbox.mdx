# Checkbox

<DocTabs>
<DocTab value="overview">

Selects an option, or several from a list, to apply when a form is
submitted.

## Variants

`variant` is the colour of the checked box. Each row: unchecked, checked,
indeterminate.

<Canvas of={CheckboxStories.Variants} />

| Variant | Use for |
| --- | --- |
| <Checkbox defaultChecked label="Neutral" /> | The default: lists, forms, tables. The checked box is the foreground colour, so a column of them stays calm. |
| <Checkbox variant="primary" defaultChecked label="Primary" /> | One checkbox that carries the brand: an opt-in, a terms box beside a primary button. |

**Indeterminate** is for a parent whose children are partly selected. It
is a display state: clicking the parent chooses all or none, never
"mixed".

## Measurements

One size. The box is 16px, Atlassian's, inside a 24px hit area, and
sits centred on the first line of its label, however many lines the
label wraps to. The label starts 8px from the box: Atlassian's 4px gap
after the 24px area.

label weight is for a field's or a group's label, not an option's.

- **Hover** anywhere on the label darkens an unchecked outline to
  `--color-text`. A checked box mixes 12% of the mark's colour into its
  fill, as Button does. An error outline stays red.
- **Focus** is a 2px `--color-border-focused` outline, 2px outside the box.
- **Disabled** dims the box and the label to 50%.
- **Read-only** looks enabled but has no hover and an arrow cursor.

### Differences from the spec

- **Atlassian's box.** 16px with a 2px corner inside a 24px hit area, and
  a 12px mark: the kit's own step, since Atlassian draws the mark as part
  of the box.
- **Base UI's and HTML's names:** `defaultChecked` and `onCheckedChange`
  for the spec's `defaultValue` (a string there, which reads as the
  submitted value: that is `value`) and `onChange`; native `disabled`,
  `required`, `readOnly` for the `is…` forms.
- **`isIndeterminate` keeps its prefix.** Indeterminate is a DOM property,
  not an HTML attribute, so by the kit's naming rule it takes `is`; Base UI
  calls it `indeterminate`.
- **`autoFocus` is applied on mount by the component.** The box is a
  focusable `<span>`, which React's own `autoFocus` ignores.
- **No `secondary`.** A light fill barely reads as checked, so only
  `neutral` (the foreground colour) and `primary` ship.

## When to use

Use a checkbox for a choice that is submitted with a form: accepting
terms, opting in, picking several items from a list. Nothing happens
until the form is sent.

Write the label so that checked means yes.

<DoDont
  do={<Story of={CheckboxStories.DoPositiveLabel} />}
  doCaption="The label says what checking does: checked means yes."
  dont={<Story of={CheckboxStories.DontNegativeLabel} />}
  dontCaption="A negative label makes unchecked a double negative, and readers stop to work it out."
/>

## When not to use

- **For a setting that applies at once.** Use a
  [Switch](?path=/docs/components-controls-switch--docs): it acts like a
  light switch, a checkbox waits for Submit.
- **For one choice out of several.** Use a
  [Radio](?path=/docs/components-controls-radio--docs) group; checkboxes
  are independent.
- **For a toggle in a toolbar.** Use a
  [Toggle Button](?path=/docs/components-buttons-togglebutton--docs).

## Accessibility

- `role="checkbox"` with `aria-checked`, `mixed` when indeterminate.
  Space toggles it.
- The label wraps the box, so it names it and clicking it toggles the box.
- `helperText` is the box's description; the error state sets
  `aria-invalid`.
- The unchecked outline is `--color-border-bold`, 3:1 on the page on every
  gray ramp.
- A hidden native input carries `name`, `value` and `required` into form
  submission and validation.
- The hit area is 24×24px, 44×44px on coarse pointers, without the box
  growing.
