# Radio

<DocTabs>
<DocTab value="overview">

Chooses exactly one option from a short list, all visible at once. The
component is `RadioGroup`.

<Canvas of={RadioStories.Default} />

## Variants

`variant` is the colour of the selected radio; `orientation` lays the
options out in a column or a row.

<Canvas of={RadioStories.Variants} />

| Variant | Use for |
| --- | --- |
| `neutral` | The default: forms and settings. The selected radio is the foreground colour. |
| `primary` | A choice that carries the brand: a plan picker beside a primary button. |

| Orientation | Use for |
| --- | --- |
| `vertical` | The default. Options with helper text, or labels longer than a word or two. |
| `horizontal` | Two to four short labels: sizes, yes or no. The row wraps when narrow. |

</States>

- **Hover** anywhere on an option's label darkens an unselected ring to
  `--foreground`. The selected radio mixes 12% of the dot's colour into
  its fill, as Button does. An error ring stays red.
- **Focus** is a 2px `--ring` outline, 2px outside the circle.
- **Disabled** dims the radio and its label to 50%, for the whole group
  or one option.
- **Read-only** looks enabled but has no hover and an arrow cursor.

### Differences from the spec

- **The component is the group.** The spec describes a single radio, but
  a radio means nothing alone: selection, arrow keys and the single tab
  stop all belong to the group. Following the kit's "flat props"
  convention, the radios are `options` rather than child components.
- **`checked` and `autoFocus` per radio are not props.** The group's
  `value` says which is checked.
- Base UI's `onValueChange` and native `disabled`, `required`,
  `readOnly` names, as on Checkbox.
- **No `secondary`.** A light fill barely reads as selected, so only
  `neutral` (the foreground colour) and `primary` ship, as on Checkbox.

## When to use

Use radios to choose one option from a short list, when seeing every
option at once helps the choice: a plan, a delivery method, a size. Up to
about six options. Select the usual choice by default when there is one.

## When not to use

- **For more than about six options, or options that do not fit on
  screen.** Use a Select, or a Combobox when the reader knows what to type.
- **For several choices at once.** Use
  [Checkboxes](?path=/docs/components-controls-checkbox--docs).
- **For a single on or off.** Use a
  [Checkbox](?path=/docs/components-controls-checkbox--docs) in a form, or a
  [Switch](?path=/docs/components-controls-switch--docs) for a setting
  that applies at once.

## Accessibility

- A `<fieldset>` with a `<legend>`, exposed as a `radiogroup` named by
  the legend.
- **One tab stop for the group.** Tab enters at the selected radio (or
  the first), arrow keys move and select, Tab leaves. Disabled options
  are skipped.
- Each option's helper text is its own description. Plain group help
  describes the group once; an error message reaches every radio, so
  whichever has focus says what is wrong.
- The unselected outline is `--control-border`, 3:1 on the page.
- A hidden native input carries `name` and `required` into form
  submission and validation.
- 44×44px touch target on each radio on coarse pointers.
