# Toggle Button

<DocTabs>
<DocTab value="overview">

A button that stays pressed: bold on or off, following or not, a filter
applied or not. It looks like a [Button](?path=/docs/components-buttons-button--docs).

<Status of={ToggleButtonStories} />

<Canvas of={ToggleButtonStories.Default} />

## Variants

Unpressed is always the same neutral button, so the pressed one is the one
that stands out. `variant` and `appearance` choose how it looks when
pressed. Each pair below: unpressed, then pressed.

<Canvas of={ToggleButtonStories.Matrix} />

| Appearance when pressed | Use for |
| --- | --- |
| `contained` | A toggle that should read as clearly on from across the screen: a filter, Follow. |
| `outlined` | A toggle among other outlined controls. Pressed, it fills neutral and keeps the variant's border. |
| `ghost` | Toolbars and dense rows: Bold, Italic, a star. Usually `isIconOnly`. |

## Color

Unpressed is the same in every variant. Pressed and `contained` takes the
variant's solid, as on Button. Pressed `outlined` and `ghost` fill with the
neutral secondary instead of a tint of the variant: a toggle stays pressed
indefinitely, so its label has to pass 4.5:1 on the fill, and red text on a
red tint measures 3.7:1.

### Differences from the spec

- **Two sizes, not four.** `sm` (24px) and `md` (32px) only, the compact control scale of the Claude apps. The spec's larger steps were dropped; a big call to action is `md` with more room around it, not a taller box.
- **`pressed`, `defaultPressed`, `onPressedChange`** instead of
  `isSelected`: Base UI's names, per the kit's convention for components
  built on it. "Pressed" is also the ARIA word (`aria-pressed`).
- **`disabled`**, not `isDisabled`.
- **`variant` and `appearance` describe the pressed state.** The spec
  applies them to the button without saying what changes when it is
  selected. If unpressed also took them, a contained toggle would look
  pressed whether it was or not.
- **A pressed outlined or ghost toggle is filled neutral, not tinted with
  its variant.** It stays in that state indefinitely, so its label has to
  pass 4.5:1 on the fill.
- **`isIconOnly`**, as on Button.

## When to use

Use a toggle for a setting that is on or off and applies immediately:
Bold, Follow, a filter. The label names the setting, and stays the same in
both states.

<DoDont
  do={<Story of={ToggleButtonStories.DoSameLabel} />}
  doCaption="The label names the setting; pressed says it is on. A screen reader hears “Follow, toggle button, pressed”."
  dont={<Story of={ToggleButtonStories.DontSwitchLabel} />}
  dontCaption="A label that flips to the action reads as “Unfollow, pressed”, which contradicts itself."
/>

## When not to use

- **For a choice submitted with a form.** Use a Checkbox or a Switch: a
  toggle applies at once, a form field waits for Submit.
- **For one of many.** Use radios or Tabs. Toggles are independent: pressing
  one does not release another.
- **For an action.** Something that happens once (Save, Send) is a
  [Button](?path=/docs/components-buttons-button--docs).

## Accessibility

- A native `<button>` with `aria-pressed`, so a screen reader announces
  "Subscribe, toggle button, pressed".
- **Keep the label the same in both states.** `aria-pressed` carries the
  state; a label that switches from "Follow" to "Unfollow" as well reads
  as "Unfollow, pressed", which contradicts itself.
- Enter and Space both toggle it.
- `isIconOnly` needs `aria-label`, as on Button.
- `isLoading` keeps it focusable but inert, as on Button.
- 44×44px touch target at `sm` and `md`, from Button.
