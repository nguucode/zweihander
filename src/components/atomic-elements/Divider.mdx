# Divider

<DocTabs>
<DocTab value="overview">

A thin line that separates content into groups: sections of a card, items
in a toolbar, blocks of a page.

<Status of={DividerStories} />

<Canvas of={DividerStories.Default} />

## Variants

| Appearance | Use for |
| --- | --- |
| `solid` | Almost everywhere: the quiet default. |
| `dashed` | A boundary that is softer or provisional: a drop zone, a "more below" break, a draft section. |

<Canvas of={DividerStories.Dashed} />

A **vertical** divider separates items in a row: toolbar groups, links in
a footer. It has no fixed height and stretches to its flex row.

<Canvas of={DividerStories.Vertical} />

**Inset** stops the line short of the container's edges, so it aligns with
the text in a padded list rather than running edge to edge.

<Canvas of={DividerStories.Inset} />

One part. The line is a border, top for horizontal and start for
vertical, and the box shrinks to it: a vertical divider is exactly as
wide as its line.

## Measurements

Thickness is whole pixels, not a token: the token layer has no
border-width scale, and a rule should stay a crisp pixel at every
`--scaling`.

| Size | Thickness |
| --- | --- |
| `sm` | 1px |
| `md` | 2px |
| `lg` | 4px |

## States

A divider is not interactive: no hover, focus or pressed. It looks the same
whether it is announced or decorative; only a screen reader tells them
apart.

Every other `<hr>` attribute passes through, including `ref` and
`aria-hidden`.

### Differences from the spec

- **`appearance`, not `variant`.** In this kit `variant` always means a
  colour by intent (primary, destructive…) and `appearance` means a style.
  Solid versus dashed is a style.
- **Thickness is raw px.** The token layer has no border-width scale, and
  a divider is the only component that needs three.

## When to use

Use a Divider between groups that spacing alone does not separate: the
sections of a menu, the blocks of a settings page, groups in a toolbar.
Divide groups, not every item: a line after each row turns a list into
stripes and makes the real breaks harder to see.

<DoDont
  do={<Story of={DividerStories.DoDivideGroups} />}
  doCaption="One line between two groups: the break carries meaning."
  dont={<Story of={DividerStories.DontDivideEveryItem} />}
  dontCaption="A line after every item: nothing stands out as a group."
/>

## When not to use

- **Where space already separates.** Cards, list items with padding and
  headed sections are grouped by their own whitespace; a line adds noise.
- **As the only thing that tells groups apart.** The line is faint on
  purpose (see Accessibility). Pair it with a heading or space.
- **For a border of a component.** Draw that with the component's own
  border, not a Divider beside it.

## Accessibility

- `<hr>` is announced as a separator. Vertical dividers add
  `aria-orientation="vertical"`; horizontal ones don't, because that is
  already the default.
- If the line is purely decorative, e.g. between two icons that are
  already grouped, pass `aria-hidden` so it isn't announced at all.
- The `--border` colour is below 3:1 against the background on purpose: a
  divider is decoration and is not required to meet the non-text contrast
  ratio. Never let a divider be the only thing that tells groups apart.
