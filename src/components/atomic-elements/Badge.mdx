# Badge

<DocTabs>
<DocTab value="overview">

A small count or dot that flags something new on another element: unread
messages on an inbox, a status on an avatar.

<Status of={BadgeStories} />

<Canvas of={BadgeStories.Variants} />

## Variants

Each variant comes as a count or, with `isDot`, a dot.

| Variant | Use for |
| --- | --- |
| <Badge count={8} /> `primary` | The default: new items in the brand colour. |
| <Badge count={8} variant="accent" /> `accent` | Strong and neutral, where the brand colour would clash. |
| <Badge count={8} variant="secondary" /> `secondary` | Low emphasis: a total, not news. As a dot, Offline. |
| <Badge count={8} variant="destructive" /> `destructive` | Something needs attention: failures, overdue items. As a dot, Busy. |
| <Badge count={8} variant="success" /> `success` | As a dot, Online. |
| <Badge count={8} variant="warning" /> `warning` | As a dot, Away or Pending. |

A dot has no text to carry it, so it must reach 3:1 against the page on its

than their pill.

## States

A badge is not interactive: no hover, focus or pressed. Its states are what
it shows.

<States
  states={[
    { label: 'Count', content: <Badge count={8} /> },
    { label: 'Over maxCount', content: <Badge count={120} maxCount={99} /> },
    { label: 'Zero', content: <Badge count={0} /> },
    { label: 'Dot', content: <Badge isDot /> },
  ]}
/>

`count={0}` shows "0". Hide the badge yourself if nothing new should mean
no badge.

### Differences from the spec

- **`children` is added.** A floating badge needs something to float on.
  The badge wraps it in a `position: relative` span rather than asking
  every consumer to position the anchor themselves.
- **`accent` is the inverted neutral.** The token set has one brand hue,
  which `primary` already uses, so `accent` is foreground-on-background:
  the strongest contrast available without inventing a colour.
- **`success` and `warning` are added** from the status tokens, for
  presence and state dots.
- **`floatingPlacement` defaults to `top-end`**, the usual notification
  corner; the spec gives no default.
- **Start and end are physical** (left and right). RTL pages would get
  mirrored placement.

## When to use

Use a Badge to say something is new, or how many, on the element it
belongs to: unread messages on an inbox button, a status dot on an avatar.
A floating badge is hidden from assistive tech, so the element it sits on
carries the meaning in its own name.

<DoDont
  do={<Story of={BadgeStories.DoNameTheAnchor} />}
  doCaption="The button is named “Notifications, 4 unread”: the count reaches a screen reader too."
  dont={<Story of={BadgeStories.DontCountOnlyInBadge} />}
  dontCaption="The count lives only in the badge, which is hidden: a screen reader hears “Notifications”."
/>

Colour is never the only signal. A destructive badge still needs words
somewhere that say what is wrong, and a status dot needs `aria-label` or
a name beside it.

## When not to use

- **For a label or category.** Use a
  [Tag](?path=/docs/components-atomic-elements-tag--docs): it holds words,
  a badge holds a number.
- **For a message that needs reading.** Use an Alert or a Toast.
- **On every item of a list.** A badge flags what is new; if everything
  is, nothing stands out.

## Accessibility

- An **inline count** is plain text and is read where it sits. Inside a
  button it becomes part of the name ("Inbox 12").
- A **floating** badge is hidden from assistive tech: it sits *outside*
  the element it decorates, so it would be read as a stray number after
  it. Put the meaning in that element's name instead:
  `aria-label="Notifications, 4 unread"`.
- A **dot** has no text and is hidden too.
- Pass `aria-label` to any badge to expose it as an image with that name
  instead, e.g. a status dot on an avatar: `aria-label="Online"`.
- Contrast is checked by addon-a11y in error mode for every story.
