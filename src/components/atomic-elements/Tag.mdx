# Tag

<DocTabs>
<DocTab value="overview">

A short label that categorises or marks something: a status, a filter
chip, a person picked in a field.

## Variants

`variant` is the colour: a status, or a hue for categories. `appearance`
is the emphasis. Any variant takes any appearance.

| Variant | Use for |
| --- | --- |
| <Tag text="Neutral" variant="neutral" /> | A plain label with no status: a type, a version. |
| <Tag text="Info" variant="info" /> | Informational status: In review, Scheduled. The default. |
| <Tag text="Success" variant="success" /> | Done or healthy: Paid, Verified, Live. |
| <Tag text="Warning" variant="warning" /> | Needs attention soon: Expiring, Pending. |
| <Tag text="Danger" variant="danger" /> | Failed or blocked: Overdue, Error. |
| <Tag text="Violet" variant="violet" /> | A hue: one per category, label or owner. It carries no meaning. |

| Appearance | Use for |
| --- | --- |
| <Tag text="Subtle" /> | Most places: a tint that sits in a row of text. |
| <Tag text="Outlined" appearance="outlined" /> | Dense tables and busy surfaces, where many tints would be loud. |
| <Tag text="Solid" appearance="solid" /> | One tag that must stand out: a single status on a card. |

## Measurements

One size, Atlassian's tag: 20px tall, control tier xs (Foundations /
Sizing), so it sits in a line of text. The border is always there,
transparent unless outlined, so appearances never shift the layout.

In a line of text the tag is centred on the line, whatever the text's
size or family (the tag's own text is always the kit's sans; a mono table
cell around it changes nothing): a 20px line of body text stays 20px with a tag in it (so a Table row
stays 28px), and a taller line, like a heading's, keeps its height. Only a
line shorter than the tag, 12/16 small text, grows to 20px.

<Canvas of={TagStories.InText} />

`size` is deprecated and the prop will be removed in the next release.
`size="sm"` renders the same tag as `md` and warns once in development;
`size="md"`, the default written out, is silent.

## States

The tag itself is not interactive. Its remove button is:

<States
  states={[
    { label: 'Enabled' },
    { label: 'Hover', pseudo: 'hover' },
    { label: 'Focus', pseudo: 'focus-visible' },
  ]}
>
  <Tag text="Design" hasRemoveButton />
</States>

- **Hover** tints the button with the tag's own text colour at 15%, so it
  reads on every variant and appearance without a token for each.
- **Focus** is the `--color-border-focused` outline every control uses, drawn inset so it
  stays inside a 20px tag.
- Pressing removes nothing by itself: `onRemove` reports it, and the
  parent drops the tag from its list.

### Differences from the spec

- **The spec's four variants needed new tokens.** `info`, `success`,
  `warning` and `danger` were added to the token layer for Tag and are
  shared with Alert and Toast.
- **One size.** The spec's sizes are gone: the tag takes Atlassian's box,
  20px tall with 12/16 text and a 180px maximum width. `size` stays one
  release as a deprecated prop that changes nothing.
- **No `isRounded`.** The corner reads the control tier's radius, so it
  follows the Theme's radius preset with every other control, and turns
  into a pill under `radius="full-rounded"`.
- **The 17 hue variants are additions.** Solid is step 600 with a white
  label on every hue, in both appearances, so a row of solid tags reads as
  one set; on the warm hues (orange, amber, yellow, lime and others) that
  label falls below 4.5:1. That is accepted on purpose.
- **`startAvatar` wins over `startIcon`** if both are passed; the spec
  does not say.
- **Digits are tabular.** Every digit takes the same width, so a tag
  holding a count or a countdown does not change width as it ticks.
- **The tag does not remove itself.** `onRemove` reports the click and
  the parent drops the tag from its list, so the list stays the one
  source of truth.

## When to use

Use a Tag to label or categorise: a status on a row, the categories of an
item, the filters applied to a list, the people picked in a field. Where a
tag has to pass AA, use `subtle` or `outlined`: solid hue tags keep one
white label across hues, which the warm ones carry under 4.5:1.

<DoDont
  do={<Story of={TagStories.DoSubtleHues} />}
  doCaption="Warm hues in subtle: every label clears 4.5:1."
  dont={<Story of={TagStories.DontSolidWarmHues} />}
  dontCaption="The same hues solid: the white label falls under 4.5:1."
/>

Colour carries meaning here, so it is never the only signal: the text says
what the status is.

In a wrapped list of removable tags on touch, keep at least `--space-6`
between rows. The remove button's touch area reaches 12px above and below
a 20px tag, and neighbouring targets would overlap.

## When not to use

- **For an action.** A tag is a label; its only control is remove. Use a
  [Button](?path=/docs/components-buttons-button--docs).
- **For a choice the user toggles on and off.** Use a
  [Toggle Button](?path=/docs/components-buttons-togglebutton--docs) or a
  Checkbox.
- **For a count.** Use a
  [Badge](?path=/docs/components-atomic-elements-badge--docs).

## Accessibility

- The remove button is named **"Remove `text`"** (e.g. "Remove Design"),
  so a list of tags does not read as a row of identical "Remove" buttons.
- It is a native `<button>`: Tab to reach, Enter or Space to press.
- On touch screens (`pointer: coarse`) its hit area grows to 44×44px
  without changing how the tag looks. That area reaches 12px above and
  below a 20px tag.
- After a tag is removed, focus has nowhere to stay and drops to the page.
  If that matters, move it to the next tag's remove button, or to the
  field the tags belong to, in your `onRemove`.
- The icon and the avatar are decorative.
- Every label clears 4.5:1 in both themes, measured by the `Contrast`
  story, except solid hue tags (see Differences from the spec).
