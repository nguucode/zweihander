# Inline Alert

A one-line message that sits in the flow of a form or a section: "That
URL is taken", "Changes are saved automatically". No box, no title, no
close button. For a message about a whole page or region, use an
[Alert](?path=/docs/components-notifications-alert--docs). Our own spec:
uiguideline.com has no page for it. A plain element.

## Anatomy

| Part | What it is |
| --- | --- |
| **Icon** | The variant's icon, one line tall. Replaceable, or `false` for none. |
| **Message** | `children`, in the variant's text colour. |
| **Action** | Optional short link or button after the message. |

## Props

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `variant` | `info`, `success`, `warning`, `danger` | `info` | |
| `size` | `sm`, `md` | `md` | `body-sm` or `body`. |
| `icon` | node or `false` | variant's icon | |
| `action` | node | – | |
| `isLive` | boolean | `false` | Announce it when it appears. |

Every other `<div>` attribute passes through.

### Design notes

- **The whole line is in the variant's text colour.** Alert can keep its
  message in `--foreground` because the box carries the colour; an
  inline alert has no box, so the text does. Every `--*-text` token is
  4.5:1 on the page in both modes, so a message of any length stays
  readable.
- **Alert or Inline Alert?** Alert when the message is about a page or a
  region and may need a title, an action row or dismissing; Inline Alert
  when it is about the thing right above it.

For an error on a single field, use the field's own `validationState`
and `helperText`: it is tied to the field with `aria-describedby`. Inline
Alert is for messages about a group of fields or a whole form.

## Accessibility

- A plain `<div>` by default, read in order with the page.
- `isLive` for a message that appears in response to something (a failed
  submit): `danger` and `warning` become `role="alert"` and are read at
  once, `info` and `success` become `role="status"` and wait.
- The icon is `aria-hidden`: the words have to carry the meaning.
