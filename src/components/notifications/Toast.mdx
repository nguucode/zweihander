# Toast

<DocTabs>
<DocTab value="overview">

A short message in a corner of the screen about something that just
happened: saved, sent, moved, failed. It closes itself after a few seconds
and never blocks the page.

<Status of={ToastStories} />

<Canvas of={ToastStories.Static} />

Try it: the toast opens in the corner of this window.

## Variants

`variant` colours the icon only; the message stays in the surface's text
colour.

<Canvas of={ToastStories.VariantsStatic} />

| Variant | Use for |
| --- | --- |
| `default` | Most toasts: something done, nothing to judge. "File moved to Trash." |
| `info` | A neutral fact about what just happened: "Sync paused while offline." |
| `success` | A result worth confirming because it was not obvious: "Invite sent to 12 people." |
| `warning` | Done, with a catch: "Saved, but 2 rows were skipped." |
| `danger` | Something failed. Interrupts the screen reader. Say what to do next, and keep the way to do it on the page too. |

`promise()` adds a loading toast that becomes `success` or `danger` when
the promise settles.

<Canvas of={ToastStories.PromiseToast} />

## States

  states={[
    { label: 'Enabled' },

    { label: 'Pending', content: <Story of={ToastStories.Pending} /> },
  ]}
>
  <Story of={ToastStories.StateExample} />
</States>

- **Hover** fills the close button with `--accent`. Hovering the stack
  also pauses every toast's timer.
- **Focus** is a 2px `--ring` outline inside the action or the close
  button. Focus in the stack pauses the timers too.
- **Pending** is a `promise()` toast: a spinner in place of the icon, and
  no timer until it settles.
- **Entering** fades in and slides `--space-2` from the edge the stack grows
  from; **leaving** fades out. With reduced motion, only the fade.

## API

`ToastProvider` wraps the app once:

```tsx
const toast = useToast()
toast.add({ title: 'File moved to Trash', action: { label: 'Undo', onClick: restore } })
```

| --- | --- |
| `add(options)` | Shows a toast, returns its id. |
| `update(id, options)` | Changes one in place; only the options given change. |

## When to use

Use a Toast to confirm something the reader just did, when the result is
not already visible: moved, sent, copied, saved in the background. Offer
"Undo" when it can be undone.

<DoDont
  do={<Story of={ToastStories.DoUndo} />}
  doCaption="News about something just done, with a way to undo it. Undo is also reachable from the Trash."
  dont={<Story of={ToastStories.DontMustAct} />}
  dontCaption="A problem the reader has to fix goes away in a few seconds. Put it in an Alert on the page."
/>

Keep it to a few words. A toast is read in passing, often half-noticed.

## When not to use

- **For something the reader must act on, or might need to read twice.**
  Use an [Alert](?path=/docs/components-notifications-alert--docs) on the
  page, or a Modal for a decision.
- **For an error in a form.** Use the field's own error, or an
  [Inline Alert](?path=/docs/components-notifications-inlinealert--docs)
  under the form.
- **As the only way to an action.** The toast goes away; the same action
  ("Undo") must be reachable somewhere else.
- **To confirm what is already visible.** A row that appears in a table
  needs no "Row added" toast.

## Accessibility

- The stack is a polite live region: a new toast is announced without
  interrupting. `danger` toasts (and any with `priority: 'high'`) are
  `role="alertdialog"` and announced at once.
- Each toast is a non-modal dialog named by its title, or by its
  description when it has none (as `promise()` toasts do).
- Timers pause while the pointer is over the stack or focus is in it, so
  there is time to reach the action. F6 moves focus to the stack.
- The close button is named `Dismiss`; Enter and Space press it. On touch
  screens its hit area grows to 44×44px, and a toast swipes away toward
  the nearest edge.
- A toast raised from inside a modal shows above it and is not hidden from
  assistive tech by it.
