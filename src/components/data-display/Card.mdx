# Card

<DocTabs>
<DocTab value="overview">

A surface that groups related content: a summary, a person, a setting.

<Status of={CardStories} />

<Canvas of={CardStories.Default} />

## Variants

`appearance` is how the surface stands off the page. Every appearance
takes every size and orientation.

<Canvas of={CardStories.Appearances} />

| Appearance | Use for |
| --- | --- |
| `elevated` | The default panel: a white `--card` on the off-white page, with an edge and a faint shadow. |
| `outline` | Cards in a dense grid or inside another panel, where a shadow per card is too much. |
| `unstyled` | The card's padding and layout with nothing visible, e.g. inside a surface that already has its own. |
| `surface` | A block of an AppShell page. It follows the Theme's `contentStyle`: raised like `elevated` when the content is `card`, a section set off by a rule above when it is `flat`. See [AppShell](?path=/docs/patterns-application-ui-app-shell--docs). |

`size` sets the padding and the gap between children, from 12px (`xs`) to
32px (`lg`).

<Canvas of={CardStories.Sizes} />

`orientation="horizontal"` sets the children side by side: media, text and
an action.

<Canvas of={CardStories.Horizontal} />

With `onClick` the whole card is one button; with `render={<a href />}` it
is a link.

<Canvas of={CardStories.Clickable} />

<Canvas of={CardStories.NoBorderSquare} />

## States

A plain card is a container and has no states. A clickable or link card
has these:

<States
  states={[
    { label: 'Enabled' },
    { label: 'Hover', pseudo: 'hover' },
    { label: 'Focus', pseudo: 'focus-visible' },
    { label: 'Hover, outline', pseudo: 'hover', content: <Story of={CardStories.ClickableOutline} /> },
  ]}
>
  <Story of={CardStories.Clickable} />
</States>

- **Hover** never touches the surface: muted text sits on `--card` at
  4.5:1 with no margin to spare, and darkening it 6% took muted text to
  3.9:1. An `elevated` card lifts to `--shadow-md`; an `outline` card's
  edge strengthens to `--control-border`, the 3:1 control border. An
  `unstyled` card has no hover look.
- **Focus** is a 2px `--ring` outline, 2px outside the card.
- **Pressed and disabled** have no look of their own. A card has no
  `disabled` prop: a card that cannot act is a plain card.

### Differences from the spec

- **`children`, not `content`.** Arbitrary content is what React children
  are for.
- **`orientation` defaults to `vertical`.** The spec says `horizontal`,
  which would lay a title and its description side by side.
- **`render` is added** so a card can be a link, alongside `onClick` for
  a card that acts.
- **No `filled` appearance.** The spec's tinted card was dropped to match
  the Claude apps, where a panel is a white `--card` on the off-white
  page, with an edge or a faint shadow.
- **`unstyled`** keeps the padding and layout and drops every visual.

## When to use

Use a Card to group content about one thing, so it reads as a unit: a
person, a plan, a setting. Put headings inside at the level the page
needs; the card has none of its own.

A clickable card is one button, and a button may only hold phrasing
content: use spans for its title and text, not headings or paragraphs,
and put no links or buttons inside it. If a card needs its own actions,
leave it plain and put a button in it.

<DoDont
  do={<Story of={CardStories.Horizontal} />}
  doCaption="A plain card with its own Follow button: each control is reachable on its own."
  dont={<Story of={CardStories.DontNestButtons} />}
  dontCaption="A button inside a clickable card is invalid HTML, and neither control can be reached reliably."
/>

A card that navigates should be a link (`render={<a href />}`), not a
button with a click handler: a link opens in a new tab and shows its
address.

<Canvas of={CardStories.Link} />

## When not to use

- **For rows of data to compare.** Use a
  [Table](?path=/docs/components-data-display-table--docs): columns line
  values up, cards do not.
- **To show and hide content.** Use an
  [Accordion](?path=/docs/components-data-display-accordion--docs) or a
  [Collapse](?path=/docs/components-data-display-collapse--docs).
- **Just to add space or a background.** A plain `<div>` with padding
  does that without suggesting a unit.

## Accessibility

- A plain card is a `<div>`: no role, no tab stop, nothing added to the
  accessibility tree.
- **A clickable card is one `<button type="button">`, so everything inside
  becomes its label.** Click, Enter and Space all call `onClick`.
- A link card is a real `<a href>`, in the tab order, with no `type`.
- The card has no heading of its own.
- Muted text clears 4.5:1 on every appearance, in both modes, at rest and
  on hover: hover changes the shadow or the edge, never the surface under
  the text. The `Contrast` story measures it.
