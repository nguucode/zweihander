# Table

<DocTabs>
<DocTab value="overview">

Rows of records with the same fields, to scan and compare: projects,
invoices, members. Columns can sort, rows can be selected, expanded and
acted on, and a total row can sum them up.

<Status of={TableStories} />

<Canvas of={TableStories.Selectable} />

## Variants

Table has one size: 8px round each cell, so a row of text is
36px, and a row that holds a button or a field grows to fit it. Any table
takes any of these together: a selectable table can also expand its rows
and keep its header in view.

| Variant | Use for |
| --- | --- |
| `isSelectable` | Acting on several rows at once: archive, export, assign. |
| `expandedContent` | Details that belong to one row but do not fit in a column: a description, a timeline, line items. |
| `hasStickyHeader` | Long tables that scroll inside a fixed height, so the column names stay in view. |
| `rowActions` | Actions on one record (edit, duplicate, archive) that do not earn a column: a menu at the row's end. |
| `footer` on a column | A total row under the rows: sums, counts, averages. |
| `isResizable` | Tables whose columns hold text of unknown length (names, notes, emails), so people can widen what they read. |
| `emptyState` | Saying why there are no rows, and what to do: clear a search, add the first one. |

## Anatomy

<Anatomy parts={TableStories.anatomyParts}>
  <Story of={TableStories.Anatomy} />
</Anatomy>

The table sits in a container that scrolls sideways on a narrow screen
rather than squeezing the columns. The selection column comes first, then
the expand column; the actions column comes last. A row whose
`expandedContent` or `rowActions` returns nothing leaves that cell empty.
The total row is a `<tfoot>`, so it stays at the bottom whatever the sort.

## Measurements

A row has no height of its own: it is as tall as what its cells hold.

| What the row holds | Row height |
| --- | --- |
| One line of text (20px), or a Tag | 36px |
| A checkbox, an expand button or an actions button (24px) | 36px |
| A 24px button | 40px |
| A 32px button or field | 48px |
| Header (one 16px line) | 32px |

A body row is exactly that tall: there is no divider under it. The header
and the total row add their 1px rule, and a table that has rows adds one
more under its last row. The checkbox, expand and actions
columns take 2px less block padding than the other cells, so their 24px
buttons do not make a row of text taller.

The handle line is 1px at rest; no token covers a hairline. Its strip is 16px wide (44px on touch screens), at the
header's end, over the header's own padding. The last column's handle sits on the table's edge and shows its line
only on hover and drag. A column is 48px to 1200px wide; the arrow
keys move it 16px at a time.

Rows have no divider between them: the hover tint and the selection fill
tell them apart. The header ends on a 1px rule and its labels are
semibold; the total row sits under the same rule, so the sum reads as a
sum. A table that has rows closes on that rule too, as Atlassian's dynamic
table: under the last row, an open row's content or the total row,
whichever comes last. It is the table's own border, so under a sticky
header it scrolls with the rows, and whatever a page puts under the table
(a Pagination, a footer) keeps its own gap below the rule. An empty table
has no closing rule: the header's is the only one over the empty state.
The sort button pulls itself out
by its own padding, so its label lines up with the cells below and its
hover fill adds nothing to the header's height.

**Every cell is padded 8px all round**, the first and last of a row
included: the first column's text, the caption and an open row's content
all start 8px in from the table's left edge, and an end-aligned last
column ends 8px short of its right edge. The control columns are their
control with 8px either side: 32px for the 16px checkbox, 40px for the
24px expand and actions buttons. Focus rings in the control columns are
drawn inside the control, because the cell has no room for an outset
ring. Figures are tabular, so numbers line up column-wide.

Each example forces the state on every row and button at once; on screen
it is the one under the pointer or the keyboard.

- **Hover** tints the row with `--color-background-neutral`, and the sort button too. The
  content row of an open row takes no hover of its own, only its row's.
- **Focus** is a 2px `--color-border-focused` outline, drawn 2px inside the sort button.
  The checkboxes and the expand button keep
  their own focus rings.
- **Pressed** has no look of its own: the click sorts, selects or opens,
  and that state's look follows.
- **Resize handle**: hover and drag thicken its line to 2px `--color-background-brand-bold`;
  focus draws the `--color-border-focused` outline inside the handle.
- **Disabled**: Table has none. A row that cannot be acted on is a row
  without the control.
- **Sorted** shows the column's icon at full colour, pointing up or down.
- **Selected** tints the row with `--color-background-brand-subtlest`.
- **Expanded** turns the chevron to point down and opens the content row
  under it.

## API

<div style={{ overflowX: 'auto' }}>
  <ArgTypes of={TableStories} />
</div>

`TableColumn<Row>` describes one column:

- `key`: unique; also the row field shown when there is no `cell`.
- `header`: the column's label.
- `cell`: renders the cell; defaults to `row[key]`.
- `sortable`: adds a sort button to the header. It sorts by `sortValue`,
  or by `row[key]`.
- `align`: `start`, `center` or `end`. `end` for numbers and dates, so the
  digits line up.
- `width`: any CSS width, e.g. `8rem` or `20%`.
- `isRowHeader`: makes the column's cells `<th scope="row">`, the name a
  row is known by. Usually the first column.
- `footer`: this column's cell in the total row, e.g. a sum. Any column
  with one adds the row; put the label ("Total") on the row header column.
  Hidden while there are no rows.

`TableSort` is `{ key, direction }`, with direction `ascending` or
`descending`.

`size` and `density` are deprecated. Table has one size, as Atlassian's
does: `size="sm"` (and `density="sm"`) renders the same table as `md`.
Both are still accepted for one release; drop them. The kit's rule for a
deprecated prop: it warns in the development console when it is passed a
value that is not its documented default, and a renamed prop warns
whenever it is used. So `size="sm"` and any `density` warn, and
`size="md"`, the default written out, is silent.

With `sort` controlled, the table leaves the order to you. `sortRows(rows,
columns, sort)` returns the rows in the order the table would sort them,
so you can sort every row before slicing out a page.

### Differences from the spec

Cell sizing follows the Figma library: Atlassian's dynamic table with 8px
round every cell.

- **No row height, and one size.** A cell has 8px padding all round
  and the row is as tall as its content; rows were a fixed 48px
  and 40px before, picked by `density` and then `size`, which are
  deprecated.
- **No row dividers.** Only the 1px rule under the header and the one
  that closes a table with rows, as Atlassian draws them; rows are told
  apart by the hover tint and the selection fill.
- **The total row has a 1px rule above it.** Atlassian's table has no
  total row; the rule is the header's, turned over. The table's closing
  rule then sits under the total row.
- **No header fill, and padded edges.** The header is its labels over the
  rule, as Atlassian's dynamic table. Unlike Atlassian's, the first and
  last cells keep their 8px at the table's edge. The hover and selection
  tints run edge to edge.
- **The caption** sits 24px from the top and 8px above the table, 8px in
  from the edge where the cells' text starts. Its type stays the cells' size,
  semibold; Atlassian's is a 20px heading.

## When to use

Use a Table for records that share their fields, when people compare them
or look one up: projects, invoices, members. Align numbers and dates to the
end, and mark the column a row is known by with `isRowHeader`.

## When not to use

- **For records that do not share fields**, or that are read one at a
  time, like products in a shop. Use [Cards](?path=/docs/components-data-display-card--docs).
- **For layout.** A table announces rows and columns to a screen reader;
  use CSS grid to place things side by side.
- **For a spreadsheet**, where arrow keys move between cells and cells
  are edited in place. Table is a plain table, not an ARIA grid; the kit
  has no data grid yet.

## Accessibility

- A real `<table>` named by its `<caption>`, with `<th scope="col">`
  headers and a `<th scope="row">` for the row header column: screen
  readers announce the column and the row for every cell.
- Sortable headers carry `aria-sort` (`ascending`, `descending` or
  `none`); the sort control is a button inside the header.
- Row checkboxes are named after the row header ("Select Atlas"), or
  "Select row 1" without one, counted from `rows` so a sort does not
  rename them. The header checkbox is "Select all rows" and reports
  `mixed` when some are selected. A selected row has `aria-selected`.
- Each expand button is named after the row header ("Expand Atlas"),
  reports `aria-expanded`, and while open points at the content cell with
  `aria-controls`. Enter and Space toggle it. The name stays the same open
  or closed; `aria-expanded` carries the state.
- A row with nothing to expand has no button.
- The expand column's header is "Details", visually hidden, so the column
  is announced like the others.
- The content cell spans every column, so it is read as one cell under its
  row.
- Each row actions button is named after the row header ("Actions for
  Atlas") and reports `aria-haspopup="menu"`. Enter opens the menu,
  Escape closes it, and focus returns to the button. A row with no items
  has no button.
- The actions column's header is "Actions", visually hidden.
- When the table is wider than its box and nothing in it takes focus, the
  scroll box becomes a tab stop with a focus ring: `role="region"` named by
  the caption, which the browser scrolls with the arrow keys. A table that
  fits, or whose cells hold a control (a sort button, a checkbox), gets no
  extra tab stop.
- With `isResizable`, each column header holds a focusable
  `role="separator"` with `aria-orientation="vertical"`, named "Resize"
  and the header ("Resize Owner"), or the column's `key` when the header
  is not plain text. Its `aria-valuenow` is the column's
  width in px, between `aria-valuemin` 48 and `aria-valuemax` 1200.
- Arrow Right widens the column 16px and Arrow Left narrows it (mirrored
  in right-to-left); Home sets the narrowest width and End the widest.
  Dragging the handle does the same with a pointer.
- The total row is in a `<tfoot>` with one cell per column, so each total
  is announced under its column; the label column is its row header.
