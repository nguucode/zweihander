# Error State

<DocTabs>
<DocTab value="overview">

What a list, a panel or a page shows when loading it failed: what went
wrong, and a way forward, usually "Try again".

<Status of={ErrorStateStories} />

<Canvas of={ErrorStateStories.Default} />

## Variants

| Variant | Use for |
| --- | --- |
| With details | A failure support may need to trace: an error code or request id under the description, selected in one click. |
| Default title | The last resort, for a failure you cannot describe: "Something went wrong". |
| `sm` | A panel, a card or a table body that failed on its own while the rest of the page loaded. |

## When to use

Use an Error State in place of content that failed to load: a list, a
panel, a whole page. Say what failed in the reader's words, say that
nothing is lost when that is true, and offer a way forward.

<DoDont
  do={<Story of={ErrorStateStories.Default} />}
  doCaption="Say what failed, that nothing is lost, and offer to try again."
  dont={<Story of={ErrorStateStories.DontRawError} />}
  dontCaption="A raw error is for developers, and with no action the reader is stuck."
/>

Details are for support, not for the reader: keep them small and
selectable so they can be pasted into a message.

## When not to use

- **When there is simply nothing there.** Use an
  [Empty State](?path=/docs/components-states-emptystate--docs).
- **When an action failed but the screen is fine**, such as a save. Use an
  Alert or a Toast and keep the reader's work on screen.
- **For a field's error.** Show it on the field, through its own error
  message.

## Accessibility

- The title is a real heading, as on Empty State. Set `headingLevel` to
  fit the outline.
- The icon is `aria-hidden`; the title says what failed.
- `isLive` makes it a `role="alert"`: use it when the error replaces
  content that was loading, so a screen reader hears that it failed.
  Without it, nothing is announced.
