# Progress Bar

<DocTabs>
<DocTab value="overview">

Shows how far a task with a known size has got: an upload, an install,
the steps of a setup.

<Status of={ProgressBarStories} />

<Canvas of={ProgressBarStories.ValueLabel} />

## Variants

`variant` is the colour of the fill, by meaning. The track is the same in
all four.

<Canvas of={ProgressBarStories.Variants} />

| Variant | Use for |
| --- | --- |
| `primary` | The default: a task the user started and is waiting on. |
| `accent` | A strong fill in neutral black or white, where the brand colour would clash or already means something else. |
| `secondary` | Low emphasis: progress in the background, or one of many bars in a list. |
| `destructive` | A task that is failing, or a quota about to run out. |

`size` is the track's thickness, and `isRounded` gives it pill ends.

<Canvas of={ProgressBarStories.Sizes} />

When a task has started but its size is not known yet, go indeterminate,
and switch to a value as soon as there is one.

<Canvas of={ProgressBarStories.Indeterminate} />

## Color

The fill is what carries the value, so it must clear 3:1 against the
track. Not every accent's solid does (amber's is about 2.9:1 on white), so
each variant fills with a colour meant to be read as text on the page,
which keeps it at 3:1 or better on the track. Switch the theme and the
accent in the toolbar: the values follow.

## States

A progress bar is not interactive: it has no hover, focus or pressed
state.

<States
  states={[
    { label: 'Progress' },
    { label: 'Indeterminate', content: <ProgressBar isIndeterminate label="Connecting" /> },
    { label: 'Complete', content: <ProgressBar value={100} label="Uploaded" showValueLabel /> },
  ]}
>
  <ProgressBar value={70} label="Uploading" showValueLabel />
</States>

- **Progress** fills from the start edge, easing between values over
  `--duration-slow`.
- **Indeterminate** slides a third of the track across, once every 1.4s.
  The value label is hidden: there is no value to show.
- **Complete** is a full bar. It does not change on its own; replace or
  remove it when the task ends.

## When to use

Use a Progress Bar for a task that takes long enough to wait on and whose
size is known, or will be: an upload, an import, the steps of a setup.
Name the task in the `label`.

<DoDont
  do={<Story of={ProgressBarStories.DoNameTheTask} />}
  doCaption="The label names the task, so the reader knows what they are waiting for."
  dont={<Story of={ProgressBarStories.DontBareBar} />}
  dontCaption="A bare bar leaves sighted readers guessing what it measures, even with an aria-label."
/>

`value` is out of `max`, and the value label shows the percentage:

<Canvas of={ProgressBarStories.Max} />

Without a visible label, `aria-label` names the bar for screen readers.
Use it only where the context already says what the bar measures.

<Canvas of={ProgressBarStories.WithoutVisibleLabel} />

## When not to use

- **For a short wait with no known size.** Use a
  [Spinner](?path=/docs/components-loaders-spinner--docs).
- **For content whose shape you know.** A
  [Skeleton](?path=/docs/components-loaders-skeleton--docs) keeps the
  layout.
- **For steps the user moves through themselves.** Use a
  [Stepper](?path=/docs/components-navigation-stepper--docs): it names the
  steps, and the user can go back.

## Accessibility

- `role="progressbar"` with `aria-valuenow`, `aria-valuemin` and
  `aria-valuemax`, and `aria-valuetext` from Base UI. Indeterminate drops
  `aria-valuenow` rather than reporting 0.
- Every bar needs a name: a visible `label` (linked by Base UI) or
  `aria-label`.
- The fill clears 3:1 on the track for every variant and accent, in both
  modes. The value label is `--muted-foreground`.
- Under `prefers-reduced-motion` the fill stops easing between values and
  the indeterminate slide slows from 1.4s to 4s a pass.
- A progressbar is not a live region. If completion matters, announce it
  (a Toast, or a status message) when the task ends.
