# Sign In

A sign-in page: the logo and the title, single sign-on buttons if you have
them, then email and password. After Tailwind UI's sign-in screens,
shadcn/ui's login blocks and Carbon's login pattern. Built on the **Auth
Layout**, the frame the other auth screens (sign up, reset password,
multi-factor) share, and the kit's TextInput, Checkbox, Link, Alert and
Button.

```sh
npx shadcn@latest add https://ontheshore.biz/zweihander/r/sign-in-template.json
```

## What works

- **Single sign-on**: a full-width button per provider, then an "or" line,
  then the form. `onProviderSelect` gets the provider's `id`; send the
  reader to your identity provider from there.
- **Email and password**: Show reveals the password and turns into Hide;
  sending the form hides it again, so the browser does not keep it as
  plain text. The fields carry `autocomplete="username"` and
  `"current-password"`, so password managers fill them.
- **Checks before sending**: an empty field, or an email with no `@`, is
  marked with a message saying what to do, and the first one gets focus.
  Typing in a field clears its message. Valid values go to `onSignIn`.
- **Wrong credentials**: `onSignIn` returns (or resolves to) a message. It
  shows above the form and is announced, the password is cleared and
  focused, the email kept. Say "The email or password is incorrect", not
  which one: naming it tells an attacker which emails have accounts. If
  `onSignIn` throws or rejects, the page says "Something went wrong. Try
  again." instead.
- **Keep me signed in**, **Forgot password?** and **Sign up** are links and a
  checkbox; drop the checkbox with `hasRememberMe={false}` and the link
  with no `signUpHref`.

## Variants

**Card** (default): the form in a card on the Theme's canvas. The most
common in business software; it reads as a step apart from the app.

**Plain**: the form straight on the canvas, for a quieter page or a canvas
that is already a colour or an image. Here also without single sign-on,
Keep me signed in or sign-up, as where accounts come by invitation.

<Canvas of={SignInStories.Plain} />

**With a panel**: `aside` puts a panel beside the form from 64rem of the
page's width: a picture, a customer quote, what is new. The form keeps the
left half and lines up at its start.

## Make it yours

Replace `onSignIn` with a call to your API and return its error message;
on success, navigate away. `providers` takes `{ id, label, icon }`: the
label is the whole button text ("Continue with Google", "Sign in with
SSO"), the icon the provider's mark. The kit ships no brand marks.

## Props

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `title` | `ReactNode` | "Sign in to your account" | The page's `h1`. |
| `providers` | `{ id, label, icon? }[]` | none | Single sign-on and social buttons above the form. |
| `onProviderSelect` | `(id) => void` | | A provider's button was pressed. |
| `onSignIn` | `(values) => string \| void \| Promise<…>` | | Gets `{ email, password, remember }` once the fields pass. A returned message shows above the form; the button is busy while a promise is pending. |
| `hasRememberMe` | `boolean` | `true` | Shows "Keep me signed in". |
| `forgotPasswordHref` | `string` | `"#forgot-password"` | Where "Forgot password?" goes. |
| `signUpHref` | `string` | none | Shows "No account? Sign up". |
| `footer` | `ReactNode` | | Under the sign-up line, outside the card: legal links, "Ask your administrator". |

Every other Auth Layout prop below passes through; `children` is the
page's form.

## Auth Layout

`AuthLayout` (in `AuthLayout.tsx`) is the frame: the logo, an `h1`, an
optional line under it, the form and a footer, in one column about 25rem
wide, centred on the canvas. Every auth screen uses it, so they line up
with each other. It owns no state. The same file exports `AuthDivider`,
the "or" line, and `PasswordInput.tsx` the password field with Show / Hide
(pass `autoComplete="new-password"` where the password is being chosen;
its button is named after a text `label`, "Show confirm password", so two
on one page differ).

```sh
npx shadcn@latest add https://ontheshore.biz/zweihander/r/auth-layout.json
```

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `brand` | `ReactNode` | | The logo, above the title. |
| `title` | `ReactNode` | required | The page's `h1`. |
| `description` | `ReactNode` | | A line under the title. |
| `appearance` | `card`, `plain` | `card` | The form in a card, or straight on the canvas. Ignored with `aside`. |
| `aside` | `ReactNode` | | A panel beside the form from 64rem; hidden below. |
| `asideLabel` | `string` | | The panel's accessible name, when it says something. |
| `footer` | `ReactNode` | | Under the form, outside the card. |
| `children` | `ReactNode` | required | The form. |

Any other prop goes to the root, e.g. `style` to set its `min-block-size`
when the page is not the whole viewport.

## Layout

- The page fills the viewport and the column sits in its middle, both
  ways. It is about 25rem wide; on a phone it takes the full width less
  the page's padding. A long title with no spaces wraps; nothing scrolls
  sideways.
- With `aside`, from 64rem of the page's width the form and the panel
  take half each and the heading lines up at the start. Below 64rem the
  panel is hidden and the page is the centred column again, so put nothing
  in the panel the reader needs. An `<img>` in it fills the panel.
- "Keep me signed in" and "Forgot password?" share a row while they fit;
  the link drops under the checkbox when they do not.

## Accessibility

- The form is in a `main` landmark, and its one heading is the `h1`. The
  panel is a `complementary` landmark after `main`, named by `asideLabel`;
  a panel that is only a picture should hold an `<img alt="">`.
- The single sign-on buttons come before the form in reading and focus
  order, as they do on screen.
- Every field has a visible label. An invalid field has
  `aria-invalid="true"` and its message as its description, and the first
  invalid field gets focus.
- The message from `onSignIn` is an `alert`, so it is announced; focus
  moves to the cleared password. The Sign in button is `aria-busy` while
  it waits, and a second press sends nothing.
- The Show button is named "Show password", then "Hide password" (after
  the field's label): its visible text is part of its name, as voice
  control needs.
- The single sign-on buttons are disabled while a sign-in is pending.
