# Forgot Password

Two pages for a forgotten password. **Forgot Password** asks for the
email, then says to check it. **Reset Password** is the page the emailed
link opens: a new password with its rules, then "Password changed". After
Carbon's login pattern. Built on the **Auth Layout** (see
[Sign In](?path=/docs/templates-auth-sign-in--docs#auth-layout)), the
`PasswordInput` Sign Up uses, and the kit's TextInput, Link, Alert and
Button.

```sh
npx shadcn@latest add https://ontheshore.biz/zweihander/r/forgot-password-template.json
```

## What works

- **Step 1, the email**: one field and Send reset link. An empty or
  malformed email is marked with a message and keeps focus. The email,
  trimmed, goes to `onRequest`.
- **Step 2, check your email**: "If an account exists for …, we sent it a
  link". It never says whether one does, so the page cannot be used to
  find out who has an account. Focus moves to the new title.
- **Resend link**: disabled for `resendCooldown` seconds (30 by default),
  showing the time left, then sends to the same email and says so. A
  failed resend shows why and starts no cooldown. It is the same button
  as OTP Input's Resend code.
- **No single sign-on buttons**: an account that signs in with a provider
  has no password here to reset.
- **Use a different email** goes back to step 1 with the email filled in.
- **Step 3, a new password** (Reset Password): the rules are listed under
  the field and ticked off as the reader types, at least 12 characters by
  default, as on Sign Up; pass your own `passwordRules`. There is no
  "confirm password" field: Show lets the reader check what they typed.
  Pass `email` to name the account and to let a password manager save the
  new password under it.
- **Password changed**: the form gives way to the title, a line and a Sign
  in button; focus moves to the title.
- **When it fails**: `onRequest` and `onChangePassword` return (or resolve
  to) a message, such as too many requests or an expired link. It shows
  above the form and is announced. If they throw or reject, the page says
  "Something went wrong. Try again."

## Make it yours

`onRequest` calls your API, which emails a link with a single-use token
when the account exists and does nothing when it does not; return a
message only for what the reader can act on (too many requests). Mount
`ResetPassword` on the page the link opens, read the token from the URL,
and send it with the password in `onChangePassword`; return a message
when the token is expired or used. A code instead of a link? Build step 2
with OTP Input, which has the same resend button.

## Props

### ForgotPassword

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `onRequest` | `(values) => string \| void \| Promise<…>` | | Gets `{ email }`, from the form and from Resend link. A returned message shows above the form and keeps the step; the button is busy while a promise is pending. |
| `resendCooldown` | seconds | `30` | Before Resend link is allowed, after each send. |
| `signInHref` | `string` | `"#sign-in"` | Where "Back to sign in" goes. |
| `footer` | `ReactNode` | | Under the Back to sign in link, outside the card. |

### ResetPassword

| Prop | Values | Default | |
| --- | --- | --- | --- |
| `email` | `string` | | The account the link is for: named under the title and given to password managers. |
| `passwordRules` | `{ label, test(password) }[]` | at least 12 characters | Listed under the password and ticked off; all must pass to send. |
| `onChangePassword` | `(values) => string \| void \| Promise<…>` | | Gets `{ password }` once the rules pass. A returned message shows above the form; otherwise the page says the password changed. |
| `signInHref` | `string` | `"#sign-in"` | Where "Back to sign in" and Sign in go. |
| `footer` | `ReactNode` | | Under the form, outside the card. |

The title and the line under it change with the step, so neither takes
`title` or `description`. Every other Auth Layout prop passes through.

## Accessibility

- The form is in a `main` landmark, and its one heading is the `h1`.
- When a step replaces the form (Check your email, Password changed), focus
  moves to the new `h1`, so a screen reader reads the page from there and
  focus is not left on a button that is gone. Use a different email puts
  focus back in the email field.
- An invalid field has `aria-invalid="true"` and its message as its
  description, and gets focus.
- Resend link is disabled during the cooldown and its name carries the time
  left. After a resend, "We sent another link" is a `status`, announced
  politely, and focus moves to the `h1` because the button is disabled
  again.
- The password rules are the field's description, each followed by "(met)"
  or "(not met)". The message from `onRequest` or `onChangePassword` is an
  `alert`, and the button is `aria-busy` while it waits.
- The email for password managers is a `hidden` input: out of the tab order
  and the accessibility tree.
