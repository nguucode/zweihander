# File Uploader

<DocTabs>
<DocTab value="overview">

Choose files to send: drag them onto the drop zone or pick them with the
button. It checks type, size and count, lists what was chosen, and shows
progress or an error per file. It does not upload: your code does, and
tells it how that is going.

<Status of={FileUploaderStories} />

<Canvas of={FileUploaderStories.WithStatus} />

## Variants

| Mode | Use for |
| --- | --- |
| `multiple` | Attachments, a batch of photos: files are appended, up to `maxFiles`. |
| Single | One document: an invoice, a CV. A new file replaces the chosen one, if it passes the checks. |

<Canvas of={FileUploaderStories.Single} />

Each file gets a type icon: a page with a coloured badge for Word, Excel,
PowerPoint, PDF, image and audio, after Microsoft 365, from the extension
or MIME type. Anything else is the bare page.

- **Dragging**: while a file is over the drop zone its edge turns solid
  `--ring` and it fills with `--accent`, so the change is not colour
  alone.
- **Rejected or required and empty**: the drop zone's edge turns
  `--danger-text` and the errors list why, one line per file.
- **Focus** is the Choose button's and the remove buttons' own ring.
- **Uploading**: a progress ring beside the remove button while
  `progress` is under 100; it goes at 100. An `error` takes its place.
- **Disabled** fades the icon and the buttons, not the text: none of it
  is a native label, so faded text would fail contrast rather than be
  exempt.

### Design notes

- **Checks on every path in.** The system picker filters by `accept`, but
  a drop, or "All files" in the picker, does not. The uploader checks the
  type, size and count of everything and says why a file was left out.
- **A rejected file never replaces a good one.** In single-file mode a
  new file replaces the chosen one only if it passes the checks.
- **The same file twice is one file.** Name, size and modified time
  match, so it is skipped rather than listed again.
- **Uploading is yours.** Start it in `onFilesChange` and report through
  `getFileStatus`.

## When to use

Use a File Uploader to attach files to a form: receipts to a claim,
documents to an application. Say what is allowed in `helperText`, and set
`accept`, `maxSize` and `maxFiles` to match, so the rules are read before
a file is turned away.

<DoDont
  do={<Story of={FileUploaderStories.DoStateTheRules} />}
  doCaption="The rules up front: types and size in the helper text, checked by accept and maxSize."
  dont={<Story of={FileUploaderStories.DontHideTheRules} />}
  dontCaption="No rules shown: people learn them one rejection at a time."
/>

Report upload progress per file with `getFileStatus`, and keep errors
short ("Upload failed"): the row has room for a few words.

## When not to use

- **For text people could paste.** Use a
  [Textarea](?path=/docs/components-inputs-textarea--docs).
- **For a link to a file.** Use a
  [Text Input](?path=/docs/components-inputs-textinput--docs) with
  `type="url"`.

## Accessibility

- Dragging is a shortcut, never the only way: the Choose button is a
  real button, reached by Tab, and opens the system picker. The file
  input itself is hidden from assistive tech so there is one control, not
  two.
- The uploader is a `group` named by its label; `required` adds
  "(required)" to that name, since a group cannot be `aria-required`.
  Submitting it empty shows "Choose at least one file." (or "Choose a
  file.") in the errors and moves focus to the Choose button, instead of
  the browser's bubble on the hidden input.
- The helper text and any errors describe the Choose button, so they
  are read when focus lands on it.
- A polite status line announces "2 files added. 1 not added." and
  "report.pdf removed."
- Remove buttons are named "Remove report.pdf". After a remove, focus
  moves to the next file's button, or back to Choose when the list is
  empty, so it is never lost.
- The progress ring is a `progressbar` named "Uploading report.pdf",
  with its value.
- While dragging, the drop zone's edge turns solid as well as changing
  colour.
