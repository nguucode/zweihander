# Select

<DocTabs>
<DocTab value="overview">

Chooses one option from a list that opens below the field. The field is
[Text Input](?path=/docs/components-inputs-textinput--docs)'s.

<Status of={SelectStories} />

<Canvas of={SelectStories.Default} />

## Variants

One appearance, the white outlined box. What changes is the size and the
validation state.

<Canvas of={SelectStories.Sizes} />

| Size | Use for |
| --- | --- |
| `md` | Forms and dialogs: the default. |
| `sm` | Dense places: toolbars, table filters. The list keeps 32px options. |

<Canvas of={SelectStories.Validation} />

| Validation state | Use for |
| --- | --- |
| `default` | Before anything is checked. |
| `error` | Nothing chosen where a choice is required, or a choice that cannot be accepted. `helperText` says which. |
| `success` | Rare: a choice checked and accepted elsewhere. |

## Anatomy

<Anatomy parts={SelectStories.anatomyParts}>
  <Story of={SelectStories.Anatomy} />
</Anatomy>

The **options list** opens below the field, 4px away, at least as wide as
the field. It renders in a portal at the end of `<body>`, so it is not
marked above. Each **option** is inset by the field's own padding, so its
text starts where the field's text does; the chosen one has a check
before its label, in the brand colour. Open the list in the example at
the top of Overview to see it.

  <Select label="Priority" options={['Low', 'High']} placeholder="Choose" />

- **Hover** changes nothing on the field; the cursor turns to the button cursor.
- **Focus** is the field's 2px `--ring` outline, shown from the keyboard,
  and kept while the list is open: focus moves into the list, but the
  field is still the one being chosen for.
- **Highlighted option** is where the arrow keys or the pointer are:
  `--accent` behind it. Disabled options are dimmed to 60% and skipped.
- **Loading** swaps the chevron for a spinner in the same place.
- **Read-only** fills the field with `--surface-filled`.
- **Disabled** is the enabled look at 50% opacity.

### Differences from the spec

- **Outlined only.** The spec's filled, underlined and unstyled appearances were dropped to match the Claude apps, where every select is the white outlined box.
- **Two sizes, not three.** `sm` (24px) and `md` (32px) only, the compact control scale of the Claude apps. The spec's larger steps were dropped; a big call to action is `md` with more room around it, not a taller box.
- **`onValueChange` with the value**, Base UI's name, instead of
  `onChange`.
- **Native names** for `disabled`, `readOnly`, `required`.
- **Options are strings or `{ value, label }` objects.** A bare component
  is not an option: an option needs a value to submit and compare, so a
  component goes in `label`.
- **The list opens below the field** instead of Base UI's default of
  laying it over the trigger with the selected option aligned: the
  spec's anatomy shows a list below.
- **The field keeps its focus ring while the list is open.** Focus moves
  into the list, but the field is still the one being filled.

## When to use

Use a Select to choose one option from five to about fifteen, when the
choices do not need to be compared side by side: a priority, a country
among a short list, a team member.

<DoDont
  do={<Story of={SelectStories.DoAHandful} />}
  doCaption="A handful of options, chosen once and then out of the way."
  dont={<Story of={SelectStories.DontTwoOptions} />}
  dontCaption="Two options hidden behind a click. A Switch or two radios show both at once."
/>

Give it a placeholder that says what to choose, and order the options in
a way people expect: by size or frequency, or alphabetically for names.

## When not to use

- **Two to four options.** Use radios, which show every choice at once,
  or a Switch for on and off.
- **More than about fifteen, or when people know what they want.** Use a
  [Combobox](?path=/docs/components-inputs-combobox--docs), which lets
  them type to filter.
- **Several choices.** A Select picks one. Use checkboxes or a
  multi-select Combobox.
- **To run an action** such as Export or Delete. Use a Menu: a Select
  keeps a value, a Menu does something.

## Accessibility

- The field is a `<button>` with `role="combobox"`,
  `aria-haspopup="listbox"` and `aria-expanded`; the list is a `listbox`
  of `option`s, with `aria-selected` on the chosen one.
- **Keyboard:** Space, Enter or Up/Down open it; the arrows move, typing
  jumps to a matching option, Enter selects, Escape closes, and focus
  returns to the field.
- The label is associated with the field (`aria-labelledby`). It is a
  `<div>`, because a `<label>` would also click the button and open the
  list.
- `helperText` is the field's description; `validationState="error"`
  sets `aria-invalid`, and `required` sets `aria-required`.
- **Read-only** locks the value, not the list: it still opens so the
  options can be read, but choosing one changes nothing. The field has
  `aria-readonly`. Use `disabled` when the list should not open at all.
- `isLoading` sets `aria-busy` on the field.
- The list renders in a portal at the end of `<body>`: it reads the
  root's tokens, so a `Theme` scope around the field does not restyle it.
- Options are 32px, 44px on touch screens.
