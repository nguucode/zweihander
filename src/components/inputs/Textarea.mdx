# Textarea

<DocTabs>
<DocTab value="overview">

Several lines of text: a message, a description, a note. The same field as
[Text Input](?path=/docs/components-inputs-textinput--docs): label, helper,
validation and sizes are shared.

## Variants

One appearance, the white outlined box. What changes is the size and how
the height is set.

<Canvas of={TextareaStories.Sizes} />

| Size | Use for |
| --- | --- |
| `md` | Forms and dialogs: the default. |
| `sm` | Dense places: a comment box in a table row, a side panel. |

<Canvas of={TextareaStories.AutoSize} />

| Height | Use for |
| --- | --- |
| `resize="vertical"` (default) | People may want to see more at once and drag the corner to get it. |
| `hasAutoSize` with `maxRows` | Text whose length varies a lot, such as a chat message: the field grows as they write, up to `maxRows`, then scrolls. |
| `resize="none"` | A fixed height the layout depends on. |

## Measurements

A textarea grows, so it has no height token: it takes block padding
instead, which puts the first line where a single-line field of the same
size puts its text. The starting height is `minRows` lines (3 by default)
plus that padding. The padding sits on the textarea, not the box, so the
resize handle lands in the field's corner.

  ]}

  <Textarea label="Note" minRows={2} placeholder="Add a note" />
</States>

- **Hover** changes nothing; the cursor turns to a text cursor.
- **Focus** is a 2px `--ring` outline around the whole box, 2px outside
  it, on click as well as keyboard. In the error state it is
  `--danger-text`.
- **Read-only** fills the box with `--surface-filled`.
- **Disabled** is the enabled look at 50% opacity.

### Differences from the spec

- **No `filled` appearance**, as on Text Input: every field is the white
  outlined box.
- Native `disabled`, `required`, `readOnly` names, and native `onChange`,
  as on Text Input.
- **`minRows` defaults to 3.** The spec gives none; the browser's own
  default of 2 is too short to read as a multi-line field.
- **`hasAutoSize`, `minRows` and `maxRows` are added**: the spec has a
  fixed `rows` only.

## When to use

Use a Textarea when the answer may run past one line: a message, a
description, feedback, an address. Set `minRows` to the length you expect,
so the field shows how much to write before anyone starts.

<DoDont
  do={<Story of={TextareaStories.DoFitTheAnswer} />}
  doCaption="A starting height that fits the answer expected tells people how much to write."
  dont={<Story of={TextareaStories.DontOneRow} />}
  dontCaption="One row looks like a single-line field and hides what has been written."
/>

Use auto-size for text whose length varies a lot, always with a `maxRows`,
so a long entry never pushes the rest of the form off the screen.

## When not to use

- **For one line**, such as a name or a title. Use a
  [Text Input](?path=/docs/components-inputs-textinput--docs): Enter can
  submit the form there.
- **For formatted text** (bold, lists, links). A Textarea is plain text;
  use a rich-text editor.
- **For a search query.** Use [Search](?path=/docs/components-inputs-search--docs).

## Accessibility

- A real `<textarea>` with its `<label>`: clicking the label focuses it,
  and the label is its accessible name.
- `helperText` is its description (`aria-describedby`);
  `validationState="error"` sets `aria-invalid="true"`. The helper text
  carries the message, not only the colour.
- `required` sets the native `required`; the label's asterisk is
  `aria-hidden`.
- Enter inserts a line break; it does not submit the form.
- Auto-size caps at `maxRows` and scrolls beyond it, so the page does not
  grow without limit and the text stays reachable by keyboard.
- The edge is the light `--field-border`, about 1.5:1, the same approved
  exception to WCAG 1.4.11 as Text Input; set
  `--field-border: var(--control-border)` where 3:1 is needed.
- Focus ring: 2px, 2px offset, around the whole field.
