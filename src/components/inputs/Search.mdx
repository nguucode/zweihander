# Search

A field for a search query, with a button to clear it. The field is
[Text Input](?path=/docs/components-inputs-textinput--docs)'s.

## Variants

One appearance, the white outlined box, in two sizes, with or without a
visible label.

<Canvas of={SearchStories.Sizes} />

| Size | Use for |
| --- | --- |
| `md` | Above a list or a page of results: the default. |
| `sm` | Toolbars and table headers, beside `sm` buttons. |

<Canvas of={SearchStories.WithLabel} />

| Label | Use for |
| --- | --- |
| None (default) | A search box whose place makes its purpose plain: a page header, above a list. It is named "Search", or by `aria-label`. |
| `label` | A search inside a form, among other labelled fields. |

- **The clear button** appears once there is a query, and not while the
  field is disabled or read-only. On hover its icon darkens to
  `--foreground`.
- **Focus** is the field's 2px `--ring` outline around the box, on click
  as well as keyboard. The clear button, when tabbed to, draws its own
  ring instead, so the two never double.
- **Read-only** fills the box with `--surface-filled`.
- **Disabled** is the enabled look at 50% opacity.

Every other `<input>` attribute passes through, including `ref`, `name`,
`autoFocus` and `onKeyDown`. `type` is always `search`.

### Differences from the spec

- **No `filled` appearance.** The spec's filled field (a tinted box with a bottom rule) was dropped to match the Claude apps, where every field is the white outlined box.
- **Two sizes, not three.** `sm` (24px) and `md` (32px) only, the compact control scale of the Claude apps. The spec's larger steps were dropped; a big call to action is `md` with more room around it, not a taller box.
- **`label` and `size` are added**, from the shared field,
  so a search box can match the form or toolbar it sits in.
- **`value` is added** for a controlled query.
- Native `disabled`, `readOnly` names.

## When to use

Use Search to find or filter: a list of components, a table, the whole
site. Say in the placeholder what is searched.

<DoDont
  do={<Story of={SearchStories.DoSaySearchWhat} />}
  doCaption="A Search field: a searchbox to assistive tech, with a clear button and Escape to clear."
  dont={<Story of={SearchStories.DontTextInputWithIcon} />}
  dontCaption="A Text Input with a search icon looks the same but is a plain textbox, with no way to clear it."
/>

When it searches the site, put it inside a `<form role="search">` (or
`<search>`) so it becomes a landmark people can jump to. The component is
only the field: filtering a list in place does not need a landmark.

## When not to use

- **To choose one value from a list.** Use a
  [Combobox](?path=/docs/components-inputs-combobox--docs): it shows the
  matches and keeps the choice.
- **For other free text.** Use a
  [Text Input](?path=/docs/components-inputs-textinput--docs).

## Accessibility

- `type="search"`, exposed as a `searchbox`, named by the visible label
  or "Search". A placeholder is not a name.
- **Clearing works the same everywhere:** the button, and Escape in the
  field (Chrome and Safari do this natively; Firefox did not). Either way
  `onChange` fires with a real event.
- The clear button is a real `<button>` named "Clear search", reached
  with Tab after the input. Pressed from the keyboard, it hands focus
  back to the field instead of losing it; a mouse press leaves focus
  where it was.
- The clear button's hit area grows to 44px on touch screens.
- The search icon is decorative and hidden from screen readers.
- The edge is the light `--field-border`, the approved exception to WCAG
  1.4.11 described on Text Input.
