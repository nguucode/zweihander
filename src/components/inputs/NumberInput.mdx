# Number Input

<DocTabs>
<DocTab value="overview">

A number, typed or stepped: a quantity, a price, a count. The field is
[Text Input](?path=/docs/components-inputs-textinput--docs)'s, with a
decrease and an increase button inside it.

<Status of={NumberInputStories} />

<Canvas of={NumberInputStories.Default} />

## Variants

One appearance, the white outlined box. What changes is the size and how
the number steps and is shown.

<Canvas of={NumberInputStories.Sizes} />

| Size | Use for |
| --- | --- |
| `md` | Forms and dialogs: the default. |
| `sm` | Dense places: a quantity in a cart row or a table cell. |

<Canvas of={NumberInputStories.Precision} />

| Setting | Use for |
| --- | --- |
| `min`, `max` | A range the value must stay in. The button at a limit is disabled. |
| `step` | Values that move in fixed amounts: 5 minutes, 0.25 of a unit. |
| `precision` | A fixed number of decimals, such as 2 for a price: `9.5` shows as `9.50`. |

## Measurements

Each size is a control tier, as on Text Input. A stepper is square and
inset 4px (`--space-1`) from the box's top and bottom, so it is the field's
height minus 8px: 16px in `sm`, 24px in `md`.

- **Hover** on a stepper fills it with `--accent` and darkens its icon; the
  field itself does not change.
- **Focus** is the field's 2px ring around the whole box, in
  `--danger-text` when invalid.
- **At a limit** the stepper that would go past it is disabled, at 50%
  opacity, and ignores hover, so it looks as unavailable as it is.
- **Read-only** fills the box with `--surface-filled`; the steppers do
  nothing.
- **Disabled** dims the whole field to 50%.

### Differences from the spec

- **No `filled` appearance.** The spec's filled field (a tinted box with a bottom rule) was dropped to match the Claude apps, where every field is the white outlined box.
- **Two sizes, not three.** `sm` (24px) and `md` (32px) only, the compact control scale of the Claude apps. The spec's larger steps were dropped; a big call to action is `md` with more room around it, not a taller box.
- **`onValueChange` with a number**, not `onChange`: built on Base UI, it
  takes Base UI's name, and the value arrives parsed rather than as text.
- **`max` is optional with no default.** The spec marks it required with a
  default of 100, which contradicts itself; a quantity with no upper
  bound is common.
- **`label`, `helperText`, `validationState`** are added
  from the shared field.

## When to use

Use a Number Input for a quantity people adjust by a little, or type
outright: guests, items in a cart, minutes, a price. Set `min` and `max`
whenever the range is known, so the steppers stop at its ends.

  do={<Story of={NumberInputStories.DoQuantity} />}

  dont={<Story of={NumberInputStories.DontIdentifier} />}
  dontCaption="A postcode is not a quantity: stepping it is meaningless, and formatting may change it."

## When not to use

- **For numbers that are identifiers**: postcodes, card numbers, phone
  numbers, IDs. Use a
  [Text Input](?path=/docs/components-inputs-textinput--docs) with
  `inputMode="numeric"`, which brings up the number keyboard without
  steppers or formatting.
- **For a value picked on a scale**, such as volume or a percentage
  people judge by eye. Use a Slider.
- **For a small fixed set of numbers** (1, 2 or 4 seats). Use radios or a
  [Select](?path=/docs/components-inputs-select--docs).

## Accessibility

- The input is a text field with `inputmode="numeric"` and the role
  description "Number field", named by the label.
- **Keyboard:** Up and Down step the value by `step` from the input; with
  Shift they step by 10, with Alt by 0.1. The steppers are out of the tab order
  (`tabindex="-1"`): the arrow keys do the same from the field.
- The steppers are named "Increase" and "Decrease" and are disabled at
  the limits, so a screen reader hears why nothing happened.
- The value is parsed and formatted in the user's locale; the form
  receives the plain number.
- `helperText` is the input's description and
  `validationState="error"` sets `aria-invalid`, as on Text Input.
- Steppers widen to 44px on touch screens, the one direction they can
  grow without covering the input or each other.
