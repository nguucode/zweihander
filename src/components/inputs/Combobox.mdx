# Combobox

<DocTabs>

A field you type into to filter a list of options, then choose one.

## Variants

Two sizes, and the field's validation states. Typing filters the list and
marks the match; the chosen option carries a check.

## Anatomy

<Anatomy parts={ComboboxStories.anatomyParts}>
  <Story of={ComboboxStories.Anatomy} />
</Anatomy>

The options list opens under the field, at least as wide as it:

- **Option**: the label, with the typed text marked by weight and
  underline. Options are inset by the field's padding, so their text
  starts where the input's does.
- **Check**: before the chosen option's label, in a column kept for every
  option so labels never shift.
- **Message**: "No matches" (`emptyText`) when nothing matches,
  "Loading…" while `isLoading`.

The field's edge is a light hairline, about 1.5:1, as in the Claude apps:
an approved exception to WCAG 1.4.11. The label, placeholder and focus
ring still mark the field. The matched text keeps the option's own colour,
so it holds full contrast on the highlighted row.

- **Focus** is a 2px `--ring` outline, 2px outside the field, drawn while
  the input has focus, by pointer too: that is where typing goes. In the
  error state the ring is `--danger-text`. The clear and open buttons draw
  their own ring when tabbed to, so the field never shows two.
- **Hover** changes nothing on the field; the clear and open buttons
  darken from `--muted-foreground` to `--foreground`.
- **Error** turns the edge and the helper `--danger-text` together; the
  words are the message, the colour only points at it.
- **Read-only** fills the field with `--surface-filled`; there is no clear
  button.
- **Disabled** is the enabled look at 50% opacity.
- **Loading** adds a spinner before the buttons and says "Loading…" in the
  list.

### Differences from the spec

- **Labels must be strings**, not components: they are what is typed,
  matched and shown in the input.
- **`emptyText`** is added: an empty list needs to say why.
- **`onValueChange`, not `onChange`**, and native names (`disabled`,
  `readOnly`, `required`), as on Select.

## When to use

Use a Combobox to choose one option from a long list, when people already
know what they are looking for: a person, a country, a project. Typing a
few letters is faster than scrolling. It chooses from the list only; free
text that is not an option is not a value.

  do={<Story of={ComboboxStories.DoLongList} />}

  dont={<Story of={ComboboxStories.DontFewOptions} />}
  dontCaption="Three options hidden behind typing. A Select or a radio group shows them all."

## When not to use

- **For a handful of options.** Under about seven, use a
  [Select](?path=/docs/components-inputs-select--docs), or a
  [Radio](?path=/docs/components-controls-radio--docs) group when they
  should all be visible.
- **For free text.** If any answer is valid, use a
  [Text Input](?path=/docs/components-inputs-textinput--docs); to filter
  a page, use [Search](?path=/docs/components-inputs-search--docs).
- **For several values.** It holds one; a multi-select is not built yet.

## Accessibility

- The input has `role="combobox"`, `aria-autocomplete="list"` and
  `aria-expanded`; the list is a `listbox` named by the field's label (or
  `aria-label` when there is no visible label), as the input is.
- **Keyboard:** typing opens and filters; the first match is highlighted
  so Enter picks it; Up and Down move; Escape closes, then clears.
- The match is marked by weight and underline, not colour, so it keeps
  the option's full contrast on the highlighted row.
- The open button is named "Show options" and is out of the tab order
  (the input already opens the list); the clear button is "Clear
  selection".
- `validationState="error"` sets `aria-invalid`, and the helper text is
  the input's description.
- Loading and empty states are announced from the list.
- After an option is picked with the pointer, the input loses focus and the
  field returns to rest (no caret, no ring). A keyboard pick keeps focus in
  the input, so keyboard and screen reader users are not dropped to the page.
- Options are 32px tall; on touch screens (`pointer: coarse`) they grow to
  44px, and the clear and open buttons get a 44×44px hit area.
