# Password Input

<DocTabs>
<DocTab value="overview">

A password field with a Show / Hide button and, where a password is being
chosen, the rules it must meet, ticked off as the reader types.

<Status of={PasswordInputStories} />

<Canvas of={PasswordInputStories.Default} />

## Variants

One appearance, Text Input's. What changes is whether the password is
being typed or chosen.

| Use | Setting |
| --- | --- |
| Signing in, or confirming who you are before a change | The default: `autoComplete="current-password"`, no rules. |
| Choosing a password: sign up, reset, change | `autoComplete="new-password"` and `rules`, so password managers suggest one and the reader sees what it needs. |

- **Hover and focus** are Text Input's; the Show button has the add-on
  button's hover and focus.
- **Shown**, the field is `type="text"` and the button reads Hide. It goes
  back to dots when the form is sent.
- **Error** colours the edge and the helper text `--danger-text`; met
  rules stay green.
- **Disabled** dims the field and disables the button.

## When to use

Use it for every password field: sign in, sign up, reset, and change
password in Settings. Give a new password `rules` so the reader knows what
it needs before sending, not after.

<DoDont
  do={<Story of={PasswordInputStories.DoWithRules} />}
  doCaption="A new password, hidden, with its rule and a Show button."
  dont={<Story of={PasswordInputStories.DontPlainText} />}
  dontCaption="A plain Text Input shows the password to anyone nearby and tells the reader nothing about what it needs."
/>

## When not to use

- **For a code that was sent**, such as a sign-in code. Use an
  [OTP Input](?path=/docs/components-inputs-otpinput--docs).
- **For an API key or token** the reader copies. Use a
  [Text Input](?path=/docs/components-inputs-textinput--docs) that is
  read-only, with a copy button.

## Accessibility

- The field is named by its label. The Show / Hide button's name says
  what it does next and to which field ("Show password", "Hide new
  password"), and its visible text is the start of that name.
- The rules are part of the field's description, each ending "(met)" or
  "(not met)", so they are read when the field gets focus; ticking one off
  is not announced on every keystroke.
- When the form is sent the field goes back to dots, so the browser does
  not keep the password as plain text in its form history.
- `autoComplete` is `current-password` by default and should be
  `new-password` where a password is chosen, so password managers fill or
  suggest the right one.
- A disabled field disables its button too.
