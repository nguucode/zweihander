## Variants

There is one appearance, the white outlined box. What changes is the
size, what sits beside the value, and the validation state.

<Canvas of={TextInputStories.Sizes} />

| Size | Use for |
| --- | --- |
| `md` | Forms and dialogs: the default. |
| `sm` | Dense places: toolbars, table filters, inline edits. |

<Canvas of={TextInputStories.PrefixSuffix} />

| Affix | Use for |
| --- | --- |
| `prefix` | A fixed start the value continues: "https://", a currency sign, an icon that says what the field holds. |
| `suffix` | A unit the value is measured in: "kg", "%", "days". |

<Canvas of={TextInputStories.Validation} />

| Validation state | Use for |
| --- | --- |
| `default` | Before anything is checked. |
| `error` | The value cannot be accepted. `helperText` says what to change. |
| `success` | A value checked against the server and accepted, such as a free username. Not for every field that passes. |

## States

<States
  states={[
    { label: 'Enabled' },

    { label: 'Read-only', content: <TextInput label="Name" defaultValue="Okami" readOnly /> },
    { label: 'Disabled', content: <TextInput label="Name" defaultValue="Okami" disabled /> },
  ]}
>
  <TextInput label="Name" placeholder="Your name" />
</States>

- **Hover** changes nothing: the field is already plainly a field, and the
  cursor turns to a text cursor.
- **Focus** is a 2px `--ring` outline, 2px outside the box, drawn on click
  as well as from the keyboard, since that is where typing will go. In the
  error state the ring is `--danger-text`.
- **Read-only** fills the box with `--surface-filled`: it can be focused
  and copied, not changed.
- **Disabled** is the enabled look at 50% opacity.

Every other `<input>` attribute passes through to the input, including
`ref`, `type`, `name`, `pattern`, `maxLength`, `inputMode` and
`autoComplete`.

### Differences from the spec

- **No `filled` appearance.** The spec's filled field (a tinted box with a bottom rule) was dropped to match the Claude apps, where every field is the white outlined box.
- **Two sizes, not three.** `sm` (24px) and `md` (32px) only, the compact control scale of the Claude apps. The spec's larger steps were dropped; a big call to action is `md` with more room around it, not a taller box.
- **Native names** for native attributes: `disabled`, `required`,
  `readOnly` rather than `isDisabled`, `isRequired`, `isReadOnly`.
- **`onChange` is the native event**, not a value: the kit's rule for
  components that wrap a real input, so it works with every form library
  as-is.
- **Changed in 0.8:** `error` became `validationState="error"` plus
  `helperText`; `forwardRef` is gone (`ref` is a prop in React 19).

## When to use

Use a Text Input for short free text on one line: a name, an email
address, a URL, a title. Give every field a visible label, and use the
placeholder only for a hint of the format.

<DoDont
  do={<Story of={TextInputStories.DoVisibleLabel} />}
  doCaption="A visible label names the field; the placeholder only hints at the format."
  dont={<Story of={TextInputStories.DontPlaceholderAsLabel} />}
  dontCaption="A placeholder as the label disappears on the first keystroke, and with it what the field was for."
/>

**Errors** say what to change, in the helper text, next to the field. The
red edge only points at the message.

<DoDont
  do={<Story of={TextInputStories.DoSayWhatToFix} />}
  doCaption="The error says what is wrong and how to fix it."
  dont={<Story of={TextInputStories.DontColourOnly} />}
  dontCaption="A red edge and 'Invalid' leave people guessing what to change."

## When not to use

- **For several lines.** Use a
  [Textarea](?path=/docs/components-inputs-textarea--docs): Enter adds a
  line instead of submitting.
- **For a quantity.** Use a
  [Number Input](?path=/docs/components-inputs-numberinput--docs), which
  steps and parses. For numbers that are identifiers (postcodes, card
  numbers, phone numbers) keep the Text Input with `inputMode="numeric"`.
- **For a search query.** Use [Search](?path=/docs/components-inputs-search--docs),
  which clears and is exposed as a searchbox.
- **To pick from a known list.** Use a
  [Select](?path=/docs/components-inputs-select--docs) or a
  [Combobox](?path=/docs/components-inputs-combobox--docs).
- **For a date.** Use a [Date Picker](?path=/docs/components-inputs-datepicker--docs).

## Accessibility

- The label is a real `<label>` for the input: clicking it focuses the
  input, and it is the input's accessible name.
- `helperText` is the input's description (`aria-describedby`), so a
  screen reader reads it after the name.
- `validationState="error"` sets `aria-invalid="true"` on the input.
  Colour is never the only signal: the helper text carries the message.
- `required` sets the native `required`; the asterisk is `aria-hidden`, so
  it is not read as "star".
- Do not rely on the placeholder as a label: it is not reliably announced
  and disappears as soon as anyone types. Without a visible label, pass
  `aria-label`.
- Pressing the field's padding or a prefix focuses the input, as a click
  anywhere on a native field does.
- **The edge is `--field-border`, about 1.5:1, a deliberate exception to
  WCAG 1.4.11** (approved 2026-10-08), for the light hairline of the
  Claude apps. The field is a white `--card` box with a faint drop on the
  off-white page, and the label, placeholder and focus ring mark it too.
  If your audience needs 3:1, set `--field-border: var(--control-border)`.
- Focus ring: 2px, 2px offset, on click and keyboard alike.
- Heights are 24 and 32px, at or above WCAG 2.5.8's 24px minimum. The
  label is part of the target, since clicking it focuses the input.
