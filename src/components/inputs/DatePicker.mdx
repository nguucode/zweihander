## Variants

Two sizes, `sm` and `md`, and the field's validation states, as on
[Text Input](?path=/docs/components-inputs-textinput--docs). The typed
order follows `locale`: day first in `en-GB` and `vi-VN`, month first in
`en-US`. The form always gets `yyyy-mm-dd`.

| Locale | Typed as |
| --- | --- |
| `en-GB`, `vi-VN` | `dd/mm/yyyy` |
| `en-US` | `mm/dd/yyyy` |

- **Focus** is a 2px `--ring` outline, 2px outside the field, drawn while
  the input has focus, by pointer too. In the error state the ring is
  `--danger-text`. The calendar button draws its own ring when tabbed to.
- **Error** turns the edge and the helper `--danger-text`. It is also
  shown on its own while the typed text is not a date, or is outside
  `min` and `max`: the helper then gives the expected pattern.
- **Hover** changes nothing on the field; the calendar icon darkens from
  `--muted-foreground` to `--foreground`.
- **Disabled** is the enabled look at 50% opacity; the calendar button is
  disabled with it.

### Design notes

- **Typing is first-class.** Many people type a known date faster than
  they can page to it. Any separator works (`3.10.26`, `3/10/2026`); the
  field reformats on blur or Enter.
- **An impossible date is kept, not guessed.** `31/02/2026` stays as
  typed, the field turns to its error state and the helper shows the
  expected pattern; nothing is reported until it is a real date.
- **A click in the input opens the calendar, and keeps focus there.**
  Typing carries on with the month in view; the calendar button and
  Alt+Down move focus into the calendar instead.
- **The form gets ISO.** Whatever the display order, `name` submits
  `yyyy-mm-dd`, so the server never has to guess the locale.
### Differences from the spec

- **`onValueChange`, not `onChange`**, with a `Date` or `null`, as the
  kit's other value fields.

## When to use

Use a Date Picker for one date: a start date, a due date, a booking. Let
people type it when they know it, and pick it when they want to see the
week around it. Set `min`, `max` or `isDateDisabled` so a date that cannot
be used cannot be chosen, rather than refusing it after submit.

## When not to use

- **For a span of days.** Use a
  [Date Range Picker](?path=/docs/components-inputs-daterangepicker--docs):
  one field, both ends, never back to front.
- **To show a month on the page.** Use a
  [Calendar](?path=/docs/components-data-display-calendar--docs) inline.
- **For a time of day.** The picker holds a date only.

## Accessibility

- The input is a labelled text box with `inputmode="numeric"` for a
  number keypad; while the text is not a valid date it has
  `aria-invalid` and the helper explains the format.
- The calendar button is named "Choose date", with the current date when
  there is one. Alt+Down in the input opens it too.
- The calendar opens as a dialog named "Choose date" with focus on the
  selected day; Escape closes it without a change.
- **After a pick the field goes back to rest.** Picked with the pointer,
  focus leaves the field (no caret, no ring), as in Combobox. Picked with
  the keyboard, focus returns to where it came from (the button, or the
  input), so keyboard and screen reader users are not dropped to the page.
- The field and calendar's own labels ("Choose date", "Previous month")
  are in English, like the rest of the kit's built-in labels.
- On touch screens (`pointer: coarse`) the calendar button gets a 44×44px
  hit area without the field growing.
