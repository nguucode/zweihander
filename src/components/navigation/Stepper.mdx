# Stepper

<DocTabs>
<DocTab value="overview">

Shows where the reader is in a flow of a few ordered steps: sign-up,
checkout, a setup wizard.

<Status of={StepperStories} />

<Canvas of={StepperStories.Default} />

## Variants

| Variant | Use for |
| --- | --- |
| Horizontal (default) | Three to five steps above a form. The label sits under its marker, so every step gets the same width whatever its label. |
| Vertical | Steps with long descriptions, or a narrow column beside the form. |
| `sm` | Dense places: a dialog, a side panel. |
| Bullets (`appearance="bullets"`) | A phone, a narrow dialog, or more steps than fit with labels: only the current step's label shows, "Step 3 of 4: Invite", over a row of dots. |
| Navigable (`onStepClick`) | Flows where going back to fix an earlier step is normal. Finished steps become buttons. |

## States

A step's status is its state. With `onStepClick`, finished steps and the
current one are buttons, with hover and focus of their own.

<States
  states={[
    { label: 'Statuses', content: <Story of={StepperStories.Statuses} /> },
    { label: 'Clickable' },
    { label: 'Hover', pseudo: 'hover' },
    { label: 'Focus', pseudo: 'focus-visible' },
  ]}
>
  <Story of={StepperStories.Clickable} />
</States>

- **Hover** underlines the label of a clickable step.
- **Focus** is a 2px `--ring` outline, 2px outside the step.
- **Upcoming** steps are never buttons, so they have no hover or focus.
- With bullets, **hover** fills the dot's hit area with `--muted`, since
  there is no visible label to underline.

## API

{/* Storybook's table does not scroll by itself on a phone. */}
<div style={{ overflowX: 'auto' }}>
  <ArgTypes of={StepperStories} />
</div>

Every other `<nav>` attribute passes through.

A step's `status` is only for the exception, such as an error: the rest
is worked out from `current`. Only finished steps can be clicked; upcoming
ones stay text, because a flow that can be skipped ahead is a set of Tabs.

Bullets ignore `orientation` and draw no connectors: the dots sit close
enough to read as one line. When `current` is past the last step, the
"Step 3 of 4" line is left out. A step with an error that is also
`current` keeps `aria-current` and the ring.

## When to use

Use a Stepper when a task is split into a few steps that must be done in
order, and it helps to know how many are left: checkout, onboarding, an
import wizard. Keep it to three to five steps with a word or two each.

<DoDont
  do={<Story of={StepperStories.DoFewShortSteps} />}
  doCaption="Four steps, one word each: the whole flow at a glance."
  dont={<Story of={StepperStories.DontTooManySteps} />}
  dontCaption="Ten steps squeeze every label and make the flow look longer than it is. Merge steps, or drop the stepper."
/>

## When not to use

- **For sections the reader can visit in any order.** Use
  [Tabs](?path=/docs/components-navigation-tabs--docs).
- **For progress with no steps to name**, such as an upload. Use a
  [Progress Bar](?path=/docs/components-loaders-progressbar--docs).
- **For a single-page form.** Headings do the job; a stepper over one page
  promises steps that are not there.

## Accessibility

- A `<nav>` landmark named "Progress" around an ordered list: screen
  readers announce the number of steps and the position of each.
- The current step has `aria-current="step"`.
- The marker is decorative, so each label carries its status in visually
  hidden text: "Account, completed", "Invite, not started", "Workspace,
  has an error". Bullets hide every label but the current one, and still
  say each in the same hidden text. Their visible "Step 3 of 4: Invite"
  is hidden from screen readers, which hear the list instead.
- An error on the current step keeps `aria-current="step"`.
- Without `onStepClick` nothing is focusable. With it, complete and
  current steps are real buttons: reached with Tab, pressed with Enter or
  Space, showing the focus ring, and 44px tall on touch screens
  (`pointer: coarse`).
