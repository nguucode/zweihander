## Variants

`appearance` is the look. Either takes either size and orientation.

| Appearance | Use for |
| --- | --- |
| `underline` | The sections of a page or a panel. Tabs sit on a 1px rule; a bar slides under the selected one. The default. |
| `pills` | A compact view switch in a toolbar, such as List / Board. A segmented track with the selected tab lifted. |

<Canvas of={TabsStories.Pills} />

| Form | Use for |
| --- | --- |
| `isFullWidth` | Two to four tabs that should fill a narrow container, such as a side panel or a phone screen. |
| `vertical` | Many sections, or labels too long for a row: settings pages, a panel beside its content. |
| Icons | Recognisable icons beside the label. Never an icon alone: the label is the tab's name. |

- **Selected**: the label takes the selected colour and the indicator
  slides under it (`underline`) or behind it (`pills`).
- **Hover** brings an unselected label up to `--foreground`. It adds no
  fill.
- **Focus** is a 2px `--ring` outline drawn just inside the tab, so it is
  not clipped by the list.
- **Disabled** (Archive, above) is the enabled look at 50% opacity. It
  still takes focus.

## When to use

Use Tabs to split one thing into views the reader moves between freely,
in any order: the overview, activity and settings of a project. Every
panel is about the same object, and only one is needed at a time.

Label each tab with a word or two. Labels do not wrap or shrink, so long
ones push the row past its container.

<DoDont
  do={<Story of={TabsStories.DoShortLabels} />}
  doCaption="Short labels, a word or two: the row fits, and each reads at a glance."
  dont={<Story of={TabsStories.DontLongLabels} />}
  dontCaption="Long labels run past the edge of the container. Shorten them, or go vertical."
/>

Use `underline` for the sections of a page and `pills` for a view switch
in a toolbar. Name the tab list with `aria-label` when no heading does.
Selection is manual by default: arrow keys move focus, Enter or Space
selects, so a slow panel does not load on every keypress. Turn on
`activateOnFocus` only for light panels.

## When not to use

- **For a sequence.** Steps that must be done in order belong in a
  Stepper.
- **To compare content side by side.** Tabs show one panel at a time; put
  things that are read together on the same view.
- **To go to another page.** Use links, a Sidebar or Breadcrumbs: a tab
  changes the view, not the URL.
- **For one setting with two or three options.** Use a radio group or a
  [Toggle Button](?path=/docs/components-buttons-togglebutton--docs) group:
  that changes a value, not the view.

## Accessibility

- `role="tablist"` of `role="tab"` buttons with `aria-selected` and
  `aria-controls`; each panel is a `role="tabpanel"` labelled by its tab.
- One tab stop: Tab moves into the list on the selected tab and the next
  Tab moves on to the panel.
- Arrow keys move between tabs (Left and Right, or Up and Down when
  vertical, with `aria-orientation` set); Home and End jump to the ends.
- Arrows move focus without selecting; Enter or Space selects. With
  `activateOnFocus`, arrows select as they go.
- A disabled tab still takes focus, marked `aria-disabled`, so it is
  found and announced, but it cannot be selected.
- Tabs are 24 or 32px tall and grow to 44px on touch screens
  (`pointer: coarse`).
- Focus ring: 2px `--ring`, drawn inside the tab.
