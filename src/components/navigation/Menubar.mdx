# Menubar

<DocTabs>
<DocTab value="overview">

A row of menus across the top of a tool, as in a desktop app: File, Edit,
View, each opening a flyout of commands. Use it in an editor-like screen
with more commands than a toolbar can show.

<Status of={MenubarStories} />

<Canvas of={MenubarStories.Default} />

## Variants

Menubar has one look. Each flyout is a
[Menu](?path=/docs/components-navigation-menu--docs) popup and takes the
same entries: actions with shortcuts, links, submenus, checkbox and radio
items, groups and separators.

| Menu | Use for |
| --- | --- |
| Enabled (the default) | Commands that apply now. |
| Disabled (`disabled`) | A menu that does not apply in the current state. It stays in place, muted, so the bar does not shift. |

## Measurements

The bar is a strip: its triggers are rows of the sm control tier, one step
shorter than the md items in the flyout. Triggers sit inset from the bar
edge by the same amount as items inside a Menu popup, and their corner
nests inside the bar's the same way.

## States

<States
  states={[
    { label: 'Closed', content: <Story of={MenubarStories.Default} /> },
    { label: 'Open', content: <Story of={MenubarStories.Open} /> },
    { label: 'Disabled menu', content: <Story of={MenubarStories.DisabledMenu} /> },
  ]}
/>

- **Hover and highlighted**: the trigger takes the same `--accent` fill as
  a highlighted item in the flyout.
- **Open**: the trigger keeps that fill while its flyout is open, so the
  reader sees which menu they are in.
- **Focus**: a keyboard focus ring inside the trigger, so it does not
  collide with its neighbours.
- **Disabled**: muted at 60% opacity, no fill on hover, skipped by the
  arrow keys.

`menus` is data, and each menu's `items` is Menu's `items`. Shortcuts are
plain trailing text, as in Menu: display only, binding the key is left to
the page.

### Differences from the spec

- **No navigation menu.** The source pairs a menubar with a navigation
  menu: links in flyouts, each with a description. Zweihänder leaves that
  out: app navigation is the Nav Sidebar and the Top Bar's links, which
  show the current page; a flyout of described links is a marketing-site
  pattern.
- **No item description.** Flyout items are Menu's entries, one line
  each. A second line of text is what a navigation menu needs, and it is
  not built.

## When to use

Use a Menubar in a screen that works like a desktop tool, an invoice or
report editor, a spreadsheet, where people look for commands by category
and learn their shortcuts. Name each menu for what it holds and keep the
order people know from desktop apps: File, Edit, View, then your own,
then Help.

  do={<Story of={MenubarStories.DoConventionalOrder} />}

  dont={<Story of={MenubarStories.DontNavigation} />}

## When not to use

- **For the app's navigation.** Use a
  [Nav Sidebar](?path=/docs/patterns-application-ui-nav-sidebar--docs) or
  the [Top Bar](?path=/docs/patterns-application-ui-top-bar--docs)'s
  links: they show where the reader is, a menubar does not.
- **For a few actions on one thing.** Use a
  [Menu](?path=/docs/components-navigation-menu--docs) from a button, or
  Buttons.
- **To find any command by name.** Add a
  [Command Palette](?path=/docs/components-navigation-command-palette--docs);
  it can sit alongside the menubar.

## Accessibility

- The bar is a `role="menubar"`, named by `aria-label`. Each trigger is a
  `menuitem` with `aria-haspopup="menu"` and `aria-expanded`; a disabled
  menu's trigger has `aria-disabled`.
- The bar is one tab stop. Arrow Left and Right move along the triggers,
  skipping disabled menus.
- Arrow Down, Enter or Space on a trigger opens its flyout on the first
  item. Inside a flyout the keys are Menu's.
- With a flyout open, Arrow Right and Left move to the next and previous
  menu and open it, and moving the pointer onto another trigger opens that
  menu instead.
- Escape closes the flyout and returns focus to its trigger; choosing an
  action closes it too.
- Shortcuts and icons are hidden from assistive tech; the label names the
  item.
- Triggers are 24px tall; on touch screens (`pointer: coarse`) their hit
  area grows to 44px.
- `isModal` (the default) makes the rest of the page inert while a flyout
  is open, so a screen reader stays in the menu.
