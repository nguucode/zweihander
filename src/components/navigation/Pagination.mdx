# Pagination

<DocTabs>
<DocTab value="overview">

Moves through a long list one page at a time: previous, next, and the page
numbers around the current one. Under a table it can also say which rows
are shown ("21–40 of 340") and let the reader pick how many rows a page
holds.

<Status of={PaginationStories} />

<Canvas of={PaginationStories.Middle} />

## Variants

Pagination has one look and one size. What changes is how many numbers
show, whether the pages are buttons or links, and the two optional ends.

| Form | Use for |
| --- | --- |
| `getHref` | Pages with their own URL: each page is a link that can be opened in a new tab and shared. |
| Buttons | Pages that only exist in this view's state, such as a filtered list in a dialog. The default. |
| `totalItems` | A table footer, where the reader needs to know how many rows there are: adds the summary at the start. |
| `pageSizeOptions` | Long tables where readers scan in bulk: adds a "Rows per page" select at the end. |

## Anatomy

<Anatomy parts={PaginationStories.anatomyParts}>
  <Story of={PaginationStories.Anatomy} />
</Anatomy>

The first and last page always show, the current page keeps a sibling
each side, and "…" appears only where it hides two or more pages. A single
hidden page is shown instead, since "…" would take the same room. So the
number of controls stays the same as you move through the middle, and
Next does not jump.

The summary and the select only appear when `totalItems` and
`pageSizeOptions` are passed. The summary sits at the start and pushes the
pages and the select to the end; on a narrow screen the row wraps.

## Measurements

One size, Atlassian Design's: the `md` control tier (Foundations /
Sizing), 32px. A control is square at its minimum; the inline padding only
shows on a page number of three digits or more. Previous and next have no
padding, so they stay square. The controls sit 4px apart, and the
ellipsis has 8px either side.

## States

<States
  states={[
    { label: 'Enabled' },
    { label: 'Hover', pseudo: 'hover' },
    { label: 'Focus', pseudo: 'focus-visible' },
  ]}
>
  <Story of={PaginationStories.StatesExample} />

- **Selected**: the current page is filled with `--color-background-brand-bold`, medium
  weight. It does not change on hover, and pressing it does nothing.
- **Hover** fills a page, Previous or Next with an `--color-background-neutral` chip.
- **Focus** is a 2px `--color-border-focused` outline, 2px outside the control.
- **Disabled**: Previous on the first page (above) and Next on the last, at 50%
  opacity. As buttons they are `disabled`; as links they lose their
  `href`.

## API

{/* Storybook's table does not scroll by itself on a phone. */}
<div style={{ overflowX: 'auto' }}>
  <ArgTypes of={PaginationStories} />
</div>

The rows-per-page select is a [Select](?path=/docs/components-inputs-select--docs)
at `size="sm"`, 32px: level with the page controls. Changing it moves to the page that holds the first row
shown before, so the reader does not lose their place; it calls
`onPageSizeChange`, then `onPageChange` if the page moved.

`size` is deprecated. Pagination has one size, as Atlassian's does:
`size="sm"` renders the same 32px controls as `md`. It is still accepted
for one release; drop it. The kit's rule for a deprecated prop: it warns
in the development console, once, when it is passed a value that is not
its documented default (or when a renamed prop is used under its old
name). So `size="sm"` warns, and `size="md"`, the default, is silent.

Every other `<nav>` attribute passes through. `paginationItems(page,
total, siblings, boundary)` is exported too, for building your own.

## When to use

Use Pagination under a long list or table when the reader needs to know
where they are in it and jump to a page: search results, an audit log, an
order history. Put it below the content it pages, and keep the list's
position stable as pages change.

Leave `siblingCount` and `boundaryCount` at 1. The control stays short and
keeps the same width as the reader moves, so Next stays under the pointer.

<DoDont
  do={<Story of={PaginationStories.DoKeepItShort} />}
  doCaption="The default range: first, last, and the current page with a neighbour each side, on one line."
  dont={<Story of={PaginationStories.DontShowEveryPage} />}
  dontCaption="Every page number at once wraps over several lines and buries the current page."
/>

Under a table, pass `totalItems` so the reader knows how much there is.
Offer `pageSizeOptions` only when readers really scan in bulk; three or
four choices (10, 20, 50, 100) are enough.

When the pages have URLs, pass `getHref`, so a page can be opened in a new
tab, bookmarked and shared.

## When not to use

- **For a feed read top to bottom.** Load more as the reader scrolls, or
  with a "Load more" [Button](?path=/docs/components-buttons-button--docs):
  page numbers mean nothing in a stream.
- **For a few items.** If everything fits on one page, show it all.
- **For the steps of a task.** Use a Stepper.
- **For switching between views of one thing.** Use Tabs.

## Accessibility

- A `<nav>` landmark named "Pagination", around a list.
- Each page control is named "Page 3"; the current one has
  `aria-current="page"`. Previous and next are named "Previous page" and
  "Next page".
- At either end, Previous or Next is disabled. As links they lose their
  `href` (the only thing that stops an `<a>` navigating) and keep
  `role="link"` with `aria-disabled`, so they are still announced as a
  disabled link.
- With `getHref`, each control is a real `<a href>`; without it, a native
  `<button>`. Both are in the tab order and activate with Enter (buttons
  with Space too).
- The summary has `role="status"`, a polite live region, so "21–40 of 340"
  is read out after a page or size change.
- The rows-per-page select is a combobox named "Rows per page"; its
  visible label is `aria-hidden` so the name is not read twice.
- The ellipsis is `aria-hidden`: the page names already say which numbers
  are there.
- Controls are 32px and grow to 44px on touch screens (`pointer:
  coarse`).
- Focus ring: 2px `--color-border-focused`, 2px offset.
