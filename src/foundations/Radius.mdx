# Radius

Rounding is a **single setting**, not a value picked per component. A
`radius` preset on `Theme` rescales everything inside it at once, and
components follow because they reference an *intent* — control, field,
panel — rather than a fixed number.

```tsx
<Theme radius="large">
  <Button>Rounder</Button>
</Theme>
```

## Presets

Five: `none`, `small`, **`medium` (the default)**, `large`, `full`. The
default is set by `--radius-factor: 1` and `--radius-full: 0px` on
`:root`, which is exactly what the `medium` preset writes — so a scope
with no `radius` prop and a scope with `radius="medium"` are identical.

<Canvas of={RadiusStories.Presets} />

Look at the `full` row. **The button becomes a pill; the input and the
panel get rounder but stop short of one.** That is the whole reason this
is a system rather than a number: a fully rounded text field reads as a
search pill in a form that isn't one, and a fully rounded card stops
looking like a container. Only controls opt all the way in.

`none` flattens every corner in the scope to `0`, including panels.

## How it works

Two variables do the work, both on `:root`:

| Variable | Default | Set by |
| --- | --- | --- |
| `--radius` | `0.625rem` | you, for the base step |
| `--radius-factor` | `1` | the `radius` preset |
| `--radius-full` | `0px` | the `radius` preset, only at `full` |

Every step is the base multiplied by the factor, so the preset scales the
whole scale rather than replacing it:

| Preset | Factor | `--radius-full` |
| --- | --- | --- |
| `none` | `0` | `0px` |
| `small` | `0.75` | `0px` |
| `medium` | `1` | `0px` |
| `large` | `1.5` | `0px` |
| `full` | `1.5` | `9999px` |

The pill is a `max()`. `--radius-control` resolves to
`max(step, var(--radius-full))` — normally the step wins because
`--radius-full` is `0px`, and at the `full` preset the `9999px` wins
instead.

Fields and panels use the same shape with a ceiling wrapped around it:

```css
max(step, min(cap, var(--radius-full)))
```

`min(cap, --radius-full)` is `0px` normally and the cap at `full`, so they
step up with the preset and stop there. Concretely, at the default base:

| Preset | `control` | `field` | `panel` |
| --- | --- | --- | --- |
| `none` | 0 | 0 | 0 |
| `small` | 6px | 6px | 10.5px |
| `medium` | 8px | 8px | 14px |
| `large` | 12px | 12px | 21px |
| `full` | pill | 15px | 27px |

The default input is 32px tall, so a pill would be 16px. `field` at
`full` lands under that on purpose, and a test asserts it.

## Three rules

### 1. Radius is tier × intent

A control's corner is not picked per component. Its **size tier** picks
the step, and its **intent** picks what happens at `full`:

| Tier | Step | Control (pill at `full`) | Field (stops one step up) |
| --- | --- | --- | --- |
| `xs` (20px) | `--radius-sm` | `--control-xs-radius` | `--control-xs-radius-field` |
| `sm` (24px) | `--radius-sm` | `--control-sm-radius` | `--control-sm-radius-field` |
| `md` (32px) | `--radius-md` | `--control-md-radius` = `--radius-control` | `--control-md-radius-field` = `--radius-field` |

The small tiers take the smaller step because the same corner on a box
two thirds the height reads as a pill. There is no `--radius-xs`: `xs`
parts are small enough that `--radius-sm` already reads as soft. See
[Sizing](?path=/docs/foundations-sizing--docs) for which component reads
which tier.

### 2. Nested corners are the outer corner minus the inset

When a rounded thing sits inside another, with an even inset, its corner
is the container's minus that inset, never its own token:

```css
.menu {
  --menu-inset: var(--space-1);
  padding: var(--menu-inset);
  border-radius: var(--radius-field);
}
.menu-item {
  border-radius: calc(var(--radius-field) - var(--menu-inset));
}
```

At the default that is 8 − 4 = 4px for a menu item, and the pills Tabs
chips are their track's corner minus the 2px track inset. A negative
result clamps to 0, so a square container gets square children. Both
corners then stay concentric at every preset; two independent tokens only
line up at one.

The rule is for concentric shapes. A close button 12px inside a popover's
corner is a free-standing control, not a nested shape, and keeps its own
step.

### 3. Radius scales with `--scaling`

Every step is multiplied by `--scaling`, as padding is. At 110% a 32px
button is 35.2px tall with 13.2px padding, and its 8px corner becomes
8.8px. Without this, the nesting rule above would hold at 100% only:
padding would shrink at 90% while the corners stayed put.

## Always round: `--radius-pill`

`--radius-pill` is `9999px` at every preset. It is for things that are
round by nature, not by preset: a badge count, an avatar, a switch track,
a slider thumb, a spinner. `--radius-full` is the preset's pill switch:
read directly it is `0` everywhere except `radius="full"`.

## Intent tokens

What components actually use.

<Canvas of={RadiusStories.Intent} />

| Token | Used by | Pills at `full` |
| --- | --- | --- |
| `--radius-control` | the md tier of Button, ToggleButton, Tabs, Pagination | yes |
| `--radius-field` | the md tier of every field, Select and Combobox lists, menus | no |
| `--radius-panel` | Card, Modal, Popover, the date picker | no |

A new component should pick the intent that matches its shape, not a step.
Getting this wrong is invisible at the default preset and only shows up
when someone sets `radius="full"` — which is exactly the kind of bug a
token system exists to prevent.

## Steps

The raw scale — `--radius-sm` through `--radius-xl` — for anything that is
genuinely decorative rather than a control, field or panel.

<Canvas of={RadiusStories.Steps} />

These follow the preset like everything else, so a decorative corner in
application code stays in step with the controls beside it.

A genuinely circular element uses `--radius-pill` (see above), not
`--radius-full`.

## Scoping and overriding

Presets nest, and `Theme` takes a `render` prop, so a single component can
opt out without a wrapper element:

```tsx
<Theme radius="full" render={<Button />}>
  Just this one is a pill
</Theme>
```

For a value the presets don't cover, set the variables directly — `tokens`
is applied after the preset, so it wins:

```tsx
<Theme radius="large" tokens={{ 'radius-factor': '2.4' }}>
```

Globally, change the base in CSS and leave the factor to the presets:

```css
:root {
  --radius: 1rem;
}
```

## One caveat about the base

The steps are offsets from the base — `sm` is `base − 4px`, not
`base × 0.6` — so a base far below the default degenerates. At
`--radius: 0.25rem` (4px) the steps are `0 / 2 / 4 / 8px` and `sm`
collapses to a square corner.

The factor does not have this problem, because it multiplies the finished
step. Prefer moving the preset over moving the base, and if the base does
need to change substantially, switch the four `calc()`s in `tokens.css`
from offsets to ratios.
