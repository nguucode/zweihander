# Spacing

{/* docs:check allow --spacing -- STALE: the kit has no --spacing; tokens are --space-* and --scaling. Page needs a rewrite (flow fix). */}

The entire spacing system is **one number**. `--spacing` is `0.25rem`
(4px), and every spacing utility multiplies it: `p-4` is
`calc(var(--spacing) * 4)` — 16px. There is no list of allowed values
anywhere in `tokens.css`, because there is no list.

## The scale is computed, not enumerated

This is the part that differs from most design systems. Where a scale is
a fixed map, `p-13` is an error because 13 is not in it. Here the value
is computed, so `p-13` (52px), `p-4.5` (18px) and `p-[7px]` all work.

That has a real consequence: **the scale cannot enforce itself.** Nothing
will stop a component from using `gap-7` where the rest of the kit uses
`gap-6`; there is no build error, no lint failure, and the result looks
almost right. The steps shown below are a convention the team keeps, not a
constraint the tooling applies.

Steps below `1` exist and are worth knowing: `0.5` (2px) and `1.5` (6px)
are what you reach for between a label and its input, or an icon and its
label — gaps where a full 4px reads as a break rather than a pairing.

## What the kit uses

Spacing steps lay out the space *between* things: a label and its input,
cards in a grid, sections of a page.

| Step | Used for |
| --- | --- |
| `1.5` (6px) | gap between a field label, its input and its helper text |
| `4` (16px) | padding inside a popover; gap between tabs and their panel |

**Inside a control, padding and gaps are not spacing steps.** They belong
to the control's size tier, with two pad variants:

| Token | `xs` | `sm` | `md` | Used by |
| --- | --- | --- | --- | --- |
| `--control-{tier}-pad` | 6px | 8px | 10px | fields and rows: text lines up with the label above it |
| `--control-{tier}-pad-spacious` | 6px | 8px | 12px | buttons: a centred label needs room either side |
| `--control-{tier}-gap` | 4px | 6px | 8px | between a control's icon and its label |

A field's option list is inset by the field's own pad, so an option's text
starts where the field's value does.

**Control heights are tokens too**, `--control-xs`, `--control-sm` and
`--control-md` at 20, 24 and 32px. One height per tier is what makes a
button, a text input, a tab and a select line up without anything being
nudged. See [Sizing](?path=/docs/foundations-sizing--docs) for the whole
tier and which component reads which.

## Customization

Change `--spacing` in `src/tokens.css` and the whole system rescales at
once. Setting it to `0.2rem` makes every gap, pad and control height in
the kit 20% tighter with no other edit.

Two cautions. The visible controls are below the 44px touch minimum on
purpose; on coarse pointers every control widens its hit area to 44px
without growing the box, so density does not cost touch users. And
because the base is in `rem`, every value inherits the user's root font
size; that is the behaviour you want, but it means "32px" is only 32px at
the default 16px root.
