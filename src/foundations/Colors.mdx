# Colors

Every color in the system is a CSS custom property declared in
`src/tokens.css`, with a counterpart under the `.dark` class. The source is
`tokens/semantic.json`; `npm run tokens` generates the stylesheet from it
and measures the contrast pairs listed below. One stylesheet holds both
modes, so a rule that reads `var(--color-text)` switches theme without a
conditional.

**The swatches on this page read their values out of the live document**,
so a color shown here is the value the components get. The token *names*
are listed by hand in `Colors.stories.tsx`.

## Naming

Names follow Atlassian's design tokens:

```
--color-<category>-<role>[-<emphasis>]
```

The **category** says what the color is painted on: `surface`, `text`,
`icon`, `border`, `background`, `interaction`, `blanket` or `chart`. Pick
the category by the CSS property you are setting — a `color` on a label is
a `text` token, a `fill` on a glyph is an `icon` token, a `background` on a
button is a `background` token. The bare category (`--color-text`,
`--color-border`) is the default for it.

The **role** says what it means: `brand`, `neutral`, `input`, `selected`,
a status (`info`, `success`, `warning`, `danger`), or `accent-<hue>`.

The **emphasis** says how strong it is, from weakest to strongest:
`subtlest`, `subtle`, (none), `bold`, `bolder`. `-inverse` is text or an
icon that sits on a `bold` fill of the same role.

In Figma the Color collection mirrors this as `<category>/<role>`:
`text/subtlest`, `background/brand-bold`, and `text/default` for the bare
`--color-text`. Each variable's code syntax is its `var(--color-…)`, so
Dev Mode shows the CSS name.

## Surfaces

What a region of the page is. `--color-surface` is the page;
`--color-surface-raised` is a card or panel set into it;
`--color-surface-overlay` is anything that floats above it — a menu,
popover, modal or toast. In light mode the page is gray-50 and the two
raised surfaces are white, so a panel separates by being lighter and needs
a border at most. In dark mode the page is the darkest step and both
raised surfaces are lifted one step toward the viewer.

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-surface` | The page | gray-50 | gray-950 |
| `--color-surface-raised` | A card or panel in the page | white | gray-900 |
| `--color-surface-overlay` | A menu, popover, modal or toast | white | gray-900 |

Text on any surface is `--color-text` (or a quieter text token below).
There is no per-surface foreground: one text token works on all three.

## Text

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-text` | Body text, headings, labels | gray-950 | gray-50 |
| `--color-text-subtle` | Text that recedes until hovered or current: navigation labels | gray-600 | gray-300 |
| `--color-text-subtlest` | Secondary text: descriptions, hints, captions, placeholders | gray-500 | gray-400 |
| `--color-text-inverse` | Text on `--color-background-neutral-bold` | gray-50 | gray-50 |
| `--color-text-brand` | Brand-coloured text: an outlined or ghost primary button, a link | accent text step | accent text step |
| `--color-text-brand-bold` | Text on `--color-background-brand-subtlest` | accent-800 or darker | accent-300 or lighter |
| `--color-text-brand-inverse` | Label on `--color-background-brand-bold` | white or near-black, per accent | near-black |
| `--color-text-<status>` | Status text on the page or on its tint | 800 | 300 |
| `--color-text-<status>-inverse` | Label on `--color-background-<status>-bold` | neutral-50 (warning: neutral-900) | neutral-900 |
| `--color-text-accent-<hue>` | Hue text on the page or on its tint | 800 | 300 |
| `--color-text-accent-<hue>-inverse` | Label on `--color-background-accent-<hue>-bolder` | neutral-50 | neutral-50 |

`--color-text-subtle` is body-safe (7.24:1 on the light page). Use
`--color-text-subtlest` for genuinely secondary text; it still clears 4.5:1
on every surface and fill it is allowed on (see Contrast).

`--color-text-brand` is a separate step from the brand fill. The fill is
picked so its label reads; read as text on the page, amber-500 is barely
2:1, so the build picks the first step of the accent that clears 4.5:1
against the page instead.

## Icons

Glyphs take `icon` tokens, not `text` tokens. They are separate so an icon
can sit at a different step from the text beside it: a status icon is the
saturated hue, its text the darker 800 step.

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-icon` | Default glyph | gray-950 | gray-50 |
| `--color-icon-subtle` | A glyph that recedes: a chevron, a field's leading icon | gray-500 | gray-400 |
| `--color-icon-inverse` | A glyph on a bold neutral fill | gray-50 | gray-50 |
| `--color-icon-brand` | A brand-coloured glyph | accent text step | accent text step |
| `--color-icon-info` | Info glyph | blue-600 | blue-400 |
| `--color-icon-success` | Success glyph | green-700 | green-400 |
| `--color-icon-warning` | Warning glyph | amber-600 | amber-400 |
| `--color-icon-danger` | Danger glyph | red-600 | red-400 |

## Borders

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-border` | A divider or container edge | gray-200 | white 10% |
| `--color-border-input` | A text field's edge | gray-300 | white 18% |
| `--color-border-bold` | A checkbox, radio or switch track outline | gray-500 | gray-400 |
| `--color-border-focused` | The focus indicator | accent-700 | accent-400 |

Choose by what the edge has to do. `--color-border` separates things and
is never the only sign something is there. `--color-border-input` is the
light hairline of a text field: about 1.5:1, a deliberate exception to 3:1
because a field also has its label, placeholder, fill and focus ring. A
product that needs 3:1 on fields sets
`--color-border-input: var(--color-border-bold)`. `--color-border-bold` is
for controls that have nothing else showing they are there, so it clears
3:1 against the page (WCAG 1.4.11). `--color-border-focused` follows the
accent one step darker than its fill, because the lighter solids miss 3:1
against the page — yellow-600 measures 2.93:1.

In dark mode the two lighter borders are translucent white, so an edge
reads the same on `--color-surface` and on a lifted
`--color-surface-raised`.

## Backgrounds

Fills behind content that is not a surface: a button, a selected row, a
filled field, a status message.

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-background-neutral` | A quiet fill: secondary button, a disabled field, a zebra stripe | gray-100 | gray-800 |
| `--color-background-neutral-bold` | A solid neutral fill (a neutral Avatar) | gray-600 | gray-600 |
| `--color-background-selected` | The current item: a selected row, the active nav item | gray-200 | white 10% |
| `--color-background-input` | A filled panel or field that subtlest text can sit on | gray-50 | gray-800 |
| `--color-background-brand-bold` | The default button: **the brand hue** | accent solid | accent solid |
| `--color-background-brand-subtlest` | A brand tint | accent-100 | accent-950 |
| `--color-background-<status>-bold` | Solid status fill | 600 (success 700, warning 500) | 400 |
| `--color-background-<status>` | Status tint | 100 | 950 |
| `--color-background-accent-<hue>-bolder` | Solid hue fill (a solid Tag) | 600 | 600 |
| `--color-background-accent-<hue>-subtler` | Hue tint | 100 | 950 |

`--color-background-brand-bold` is the one fill the
[`accentColor`](?path=/docs/foundations-overview--docs) setting moves, with
`--color-text-brand`, `--color-icon-brand`, the brand tint and
`--color-border-focused`. The accent solid is step 600 for most hues and
700 for sky, fuchsia, pink and rose in light mode, and its label is white
or near-black, whichever clears 4.5:1 on it.

## Interaction, blanket

| Token | Role | Light | Dark |
| --- | --- | --- | --- |
| `--color-interaction-hovered` | Hover overlay, laid over whatever fill the item already has | black 5% | white 6% |
| `--color-blanket` | Behind a modal | black 50% | black 50% |

`--color-interaction-hovered` is translucent so one token works on any
surface or fill: lay it on top (a second background layer or a
pseudo-element), do not swap the fill for it.

## Status and hue

Four status roles carry meaning about state: `info` (blue), `success`
(green), `warning` (amber), `danger` (red). They are fixed hues and do not
follow the accent: a status colour that changes with the brand stops being
a status. Each role has a solid fill and its label, a tint, text that reads
on the tint or the page, and an icon:

```
--color-background-<status>-bold   --color-text-<status>-inverse
--color-background-<status>        --color-text-<status>
--color-icon-<status>
```

`danger` is also the destructive action: a delete button is
`--color-background-danger-bold` with `--color-text-danger-inverse`. If the
accent is already red, tell a destructive action apart by wording and
placement, not by colour alone.

The 17 hues (`red` to `rose`, as in the primitives below) carry category,
not state — a Tag colour, an Avatar's initials. Each has a solid, its
label, a tint, and text:

```
--color-background-accent-<hue>-bolder   --color-text-accent-<hue>-inverse
--color-background-accent-<hue>-subtler  --color-text-accent-<hue>
```

Every hue's solid is step 600 with a white label in both modes, so a row of
solid tags reads as one set. The warm hues fall below 4.5:1 there, and the
build does not measure hue labels on purpose (decision of 2026-10-08).
`--color-text-accent-orange-contrast` is a near-black label (neutral-900)
for orange, for a place that has to pass 4.5:1 on the orange solid; nothing
in the kit reads it yet.

## Contrast

Measured, not assumed. `npm run tokens` computes each pair below from the
OKLCH values and stops the build if one drops under its floor. WCAG AA
wants 4.5:1 for text and 3:1 for the edge of a control or a chart mark.

- **Brand labels:** for each of the 17 accents, the solid and its label are
  picked together so `--color-text-brand-inverse` clears 4.5:1 on
  `--color-background-brand-bold`. `--color-text-brand` clears 4.5:1
  against the page, and `--color-border-focused` clears 3:1 against it.
- **Status:** for each of info, success, warning and danger, in both modes,
  `--color-text-<status>-inverse` on the bold fill, and
  `--color-text-<status>` on its tint and on the page, all at 4.5:1.
- **Hues:** `--color-text-accent-<hue>` on its subtler tint and on the
  page, at 4.5:1. Labels on the bolder fill are not measured (see above).
- **Secondary text:** `--color-text-subtlest` on `--color-surface`,
  `--color-surface-raised`, `--color-background-input` and
  `--color-background-neutral`, at 4.5:1 on all nine gray ramps in both
  modes.
- **Neutral solid:** `--color-text-inverse` on
  `--color-background-neutral-bold`, at 4.5:1 on all nine gray ramps.
- **Control outlines:** `--color-border-bold` against the page, at 3:1 on
  all nine gray ramps.
- **Chart marks:** each `--color-chart-<n>` against `--color-surface-raised`,
  at 3:1 on all nine gray ramps. This is why yellow and lime take step 700
  in light.

The values on the defaults (blue accent, gray ramp):

| Pair | Light | Dark |
| --- | --- | --- |
| `--color-text` on `--color-surface` | 19.28:1 | 19.28:1 |
| `--color-text` on `--color-surface-raised` | 20.13:1 | 17.00:1 |
| `--color-text-subtle` on `--color-surface` | 7.24:1 | 13.67:1 |
| `--color-text-subtlest` on `--color-surface` | 4.85:1 | 7.73:1 |
| `--color-text-subtlest` on `--color-background-neutral` | 4.60:1 | 5.64:1 |
| `--color-text-brand-inverse` on `--color-background-brand-bold` | 5.03:1 | 6.79:1 |
| `--color-text-brand` on `--color-surface` | 5.04:1 | 7.63:1 |
| `--color-text-inverse` on `--color-background-neutral-bold` | 7.24:1 | 7.24:1 |
| `--color-border-focused` on `--color-surface` | 6.54:1 | 7.63:1 |
| `--color-border-bold` on `--color-surface` | 4.85:1 | 7.73:1 |

| Status pair | info | success | warning | danger |
| --- | --- | --- | --- | --- |
| label on bold, light | 5.03:1 | 4.73:1 | 8.35:1 | 4.56:1 |
| text on tint, light | 7.25:1 | 6.45:1 | 6.41:1 | 6.86:1 |
| text on page, light | 8.47:1 | 6.80:1 | 6.83:1 | 8.02:1 |

The tightest pair is `--color-text-subtlest` on
`--color-background-neutral` in light mode, at 4.60:1: gray-500 on every
ramp is the lightest value that clears 4.6:1 on its own gray-100. Dark
`--color-text-danger-inverse` is neutral-900, not near-white: the danger
fill lightens to red-400 in dark mode, and near-white on red-400 is 2.77:1.

## Color is never the only signal

`--color-background-danger-bold` on a button does not say what will be
destroyed, and a red tag means nothing to a reader who cannot tell it from
a neutral one. Pair colour with words, an icon or a shape every time it
carries meaning. The numbers above are a floor, not a design review.

## Dark mode

Every token has a counterpart under `.dark`, switched by a class. Dark is
not an inversion of light: surfaces go *up*, and strong fills get lighter
so their labels flip to dark text. The mechanism and how to follow the OS
setting are on their own page:
**[Dark mode](?path=/docs/foundations-dark-mode--docs)**.

## Primitives

The palette underneath: 17 hues and 9 gray ramps, 11 shades each. Two ramps feed the semantic
tokens and each can be swapped on its own: an **accent** (blue by default)
for the brand tokens, and a **gray** (`gray` by default) for surfaces,
text, borders and neutral fills. The status, hue and chart tokens pin
their own ramps. The exceptions to "every value is a ramp step" are the
white raised surfaces in light mode and the translucent tokens: the dark
borders, dark selected fill, hover overlay and blanket.

This is raw material, not a palette to build UI from. Reach for a
primitive when you are defining the *next* semantic token; if a primitive
shows up in a component, a token is missing. The classes are generated by
an `@source inline(...)` directive in `src/index.css` only so this page
can render them.

## Customization

Redeclare a token after Marram's stylesheet, or edit
`tokens/semantic.json` and run `npm run tokens` if you own the source.
Nothing that reads `var(--color-background-brand-bold)` changes, because
every rule points at the variable rather than the value.

Two things to carry through a rebrand: re-measure the pairs above — a
brand hue at the same lightness as another will not hit the same ratios —
and keep light and dark as separate decisions. Reusing the light value of
a fill in dark mode is what produced the 2.77:1 failure described under
Contrast.

Projects that install through the registry get these values merged into
their own stylesheet; projects on the npm package import
`marram/tokens.css` and override afterwards.
