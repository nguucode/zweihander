# zweihander

## 0.8.0

### Minor Changes

- f7439ac: Components follow Atlassian's box sizing. Button: 12px inline padding, a 6px icon gap and a 14/20 label at both sizes (`sm` was 8px and 12/16). Tabs: 8px inline padding. Menu, ContextMenu, Menubar and Select options: 36px rows (8×12 padding), popups 8px radius. Checkbox and Radio: a 16px box (was 20) in a 24px hit area. Switch: `md` 32×16 and `lg` 40×20; `size="sm"` is deprecated and renders `md`. Tag: one 20px size with 12/16 text, capped at 180px; its `size` prop is deprecated. Badge: counts are 16px tall, at least 24px wide, 2px radius; `size="sm"` on a count is deprecated. Modal: 400 / 600 / 800px wide, 24px padding, a 20/24 title. Drawer: 360 / 480 / 600px. Popover, Card, Toast and Alert: 8px radius; Toast is 400px wide with 16px padding, Alert has 16px padding. Tooltip: 4×6 padding, 240px at most. Table: cells are 4×8 (`md`) or 2×8 (`sm`) and a row is as tall as its content (28 / 24px for one line of text, 40px with a 32px control); the header is 12/16 weight 600 over a 2px rule; the `density` prop is renamed `size`, and `density` is deprecated. TopBar: 48px tall (was 56) with 12px inline padding and 8px gaps; NavSidebar pads 12px and its rail is 56px. Token values: `--control-md-gap` is 6px (was 8) and `--control-sm-pad-spacious` 12px (was 8). The component-private custom properties `--tag-icon` and `--table-row` are gone. Remove the deprecated `size` values and rename `density` to `size` on Table.
- f7439ac: Fields follow Atlassian's box sizing: a field is one step taller than a button. TextInput, Textarea, Search, NumberInput, PasswordInput, Select, Combobox, DatePicker, DateRangePicker and OTPInput are 40px at `size="md"` (were 32) and 32px at `size="sm"` (were 24); there is no 24px field any more. Both sizes use 14/20 text, a 16px icon, 6px inline padding and no resting shadow. Field labels and helper text are 12/16 (labels weight 600), 4px from the box. New token `--control-lg` (40px). In a toolbar, where a field sits in a row with buttons or tabs, pass `size="sm"` so the row is 32px; Pagination's rows-per-page select and InlineEdit's input are always `sm`. The `popupInset` export of `InputField` is removed.
- 9a212ca: The remaining sizes follow Atlassian. Avatar: `xs` 16px, `sm` 24, `md` 32 (the default, was 40), `lg` 40, and new `xl` 96 and `2xl` 128; each name is one step smaller than before, so move an explicit `size` up one step to keep its pixels (`xs` → `sm`, `sm` → default, `md` → `lg`); 48px is gone. Table has one size and no dividers between rows (the header keeps its 2px rule, the total row gets one above it); its `size` prop is deprecated along with `density`. Pagination has one size (32px); its `size` prop is deprecated. `--sidebar-width` is 320px (was 256); AppContent's aside and the Settings nav column keep 256px. Fixes: a Tag no longer makes its line 1px taller (a Table row holding one is 28px), and InlineEdit at `size="sm"` fits a 28px Table row while reading and makes the row 40px while editing.
- f7439ac: Foundations follow Atlassian's scale; token names are unchanged. Radius is now six steps cut from `--radius` (6px): `--radius-xs` 2, `-sm` 4, `-md` 6, `-lg` 8, `-xl` 12, `-2xl` 16, so controls and fields are 6px (were 8), small controls 4px (were 6) and panels 12px (were 14). Elevation has two levels, `--shadow-raised` and `--shadow-overlay`; `--shadow-2xs` to `--shadow-sm` now read raised and `--shadow-md` to `--shadow-2xl` read overlay. `--text-body-xs` is 12px (was 11px) and deprecated: use `--text-body-sm`. Headings are weight 600. New tokens: `--space-5`, `--space-16`, `--space-20`, `--border-width`, `--border-width-selected`. If you set `--radius` yourself, it now names the `md` step: 0.625rem before is 0.375rem now.
- 98e96f8: The five places that still differed from Atlassian now match. Tabs: the underline list is pulled out by a tab's 8px padding again and the first tab keeps its padding, as Atlassian's; inside a container that clips, leave 8px of room on that side or the first tab's focus ring is cut. Calendar: the header is previous year, previous month, the title centred, next month, next year; the title reads the long month ("September 2026"); a year step that would pass `min` or `max` lands on the limit's month. Table: a table with rows closes on a 2px rule. NavSidebar: the head pads 12/12/4 with or without a logo and the brand row is 32px, so in the sidebar layout the logo sits 4px lower than before (its centre at 28px; 24px in the top-bar layout). ButtonGroup: one row that does not wrap.
- dc5d47b: The last deliberate deviations from Atlassian are closed. ButtonGroup is a row of separate buttons 4px apart (it was a joined bar; ToggleGroup stays joined). Table's first and last cells are flush with its edges and the header has no fill; checkbox and actions columns are 24px. Modal sits 60px from the screen's sides and top (it was centred, 16px in) and fills the screen under 480px. Calendar days are 40×32 with no gap, its month buttons 24px; a date range picker shows one month under 50rem. Picker chevrons and clear icons are 12px, with 16px between a value and its chevron; DatePicker's calendar icon is 20px from the end. Field labels, a radio group's legend and a slider's label are weight 653 through the new `--font-weight-label` token (a variable face draws 653; a static one uses the nearest weight it has). NavSidebar's head pads 12/4, its body 12, and its footer is ruled and padded 12; a label with no icon starts 10px in. The brand row and `header` slot of NavSidebar now sit in one wrapper element. Fixes: the first tab no longer sticks out of its list (its label starts at the list's edge), so it is not cut in a container that clips; CommandPalette's list is 12px from its edge; a Tag no longer inflates a line set in another font; ColorPicker's popup opens 8px under the whole field. Deprecated `size` props on Table and Pagination warn only for a non-default value. New token `--aside-width` (256px) for AppContent's aside and the Settings nav. Calendar's private `--calendar-day` and `--calendar-gap` are gone.
- 3cd250f: AppShell becomes a frame that only places its pieces, on a canvas set by the Theme.
  
  - **Theme** takes `canvas` (`plain`, `neutral` default, `tinted`) and `contentStyle` (`flat` default, `card`). A custom canvas colour or gradient goes through `tokens={{ canvas, 'canvas-solid', 'canvas-foreground', 'canvas-muted-foreground' }}`; its contrast is yours to check.
  - **AppShell** takes `layout` (`sidebar` default, `top-bar`), `topBarSurface` and `sidebarSurface` (`solid` or `transparent`), and a `brand` slot for the logo, which it places in the same spot in both layouts.
  - **Card** takes `appearance="surface"`: raised under `contentStyle="card"`, a section ruled off at the top under `flat`.
  - New token `--sidebar-width` (16rem, 14rem in Compact); Sidebar reads it.
  
  Breaking for AppShell (copy-source: copy `AppShell.tsx` and `AppShell.module.css` again, plus `Sidebar.module.css`):
  
  - In the default `sidebar` layout there is no top bar on wide screens; the `header` only shows while the sidebar is in the drawer. Keep a top bar with `layout="top-bar"`, or move search and the account into the Sidebar's `header` and `footer`.
  - The page is now one card surface inset 8px from the shell's edges (`contentStyle="flat"`), the sidebar sits on the canvas with no fill (`sidebarSurface="transparent"`), and the top bar is `--control-md` plus two `--space-cluster` tall (56px) instead of 64px.
  - AppHeader no longer draws its own background, bottom edge or sticky position: the shell's top cell does. An AppHeader used outside an AppShell needs them set by its container.
  - Pass the logo as `brand` rather than inside the Sidebar's `header` or the AppHeader's `start`.

  - **AppShell** moves to the templates (`src/components/templates/application-ui/AppShell.tsx`, registry `app-shell`, now listed as a template). Its props are unchanged.
  - **TopBar** (new pattern, registry `top-bar`) replaces `AppHeader`; **TopBarNav** replaces `AppNav`. Same props.
  - **NavSidebar** (pattern, registry `nav-sidebar`) replaces the **Sidebar** component, with the same props (`SidebarItem`, `SidebarGroup`, `SidebarEntry`, `SidebarProps` become `NavSidebar…`).
  - **AppContent** (new pattern, registry `app-content`) is the page region the shell puts around its children.
  
  Breaking:
  
  - `zweihander/sidebar` is removed from the npm package, and the `sidebar` registry item is gone. Install `nav-sidebar` from the registry and import `NavSidebar`.
  - Copy-source users: copy `AppShell.tsx` and `AppShell.module.css` from their new place, and add `TopBar`, `AppContent` and `NavSidebar` (`.tsx` and `.module.css` each). Rename `AppHeader` to `TopBar`, `AppNav` to `TopBarNav`, `Sidebar` to `NavSidebar`.
- 82614b4: Add the box ramp: `--box-2xs` to `--box-xl` (16, 20, 24, 32, 40, 48; Compact 16, 20, 22, 28, 36, 44). `--control-xs/sm/md` now alias `--box-xs/sm/md` with the same values, and the token build fails when a control, size or row token leaves the ramp.
- 63d8c40: `Card` and `Avatar` now default to `size="md"`, matching every other component that offers an `md` size. A Card without `size` gets 24px padding instead of 16px; an Avatar without `size` is 40px instead of 32px. Pass `size="sm"` to keep the old look.
- 235d87e: Density: `Theme` takes `density="default" | "compact"`. Six spacing roles (`--space-stack`, `--space-inline`, `--space-cluster`, `--space-group`, `--space-container`, `--space-section`), `--row-height`, the control tier, the type scale and component sizes (`--choice-box`, `--radio-dot-size`, `--switch-{sm,md,lg}-{w,h}`, `--progress-{sm,md,lg}`, `--avatar-{xs,sm,md,lg}`, `--badge-{sm,md}`, `--badge-dot-{sm,md}`) each have a Default and a Compact value, and every component reads them. Compact keeps every size and tightens each: md controls 32 to 28px, body text 14 to 13px, table rows 48 to 36px.
  
  Default renders as before except: the page edge in AppShell (64rem and up) and the gap between form sections go from 32 to 24px, Alert padding from 10 to 12px, and the block padding of menu items and select options from 6 to 4px (their 32px height is unchanged).
  
  Select, Combobox, DatePicker and DateRangePicker take `container` for their popup, like Popover and Menu, so a scope with its own density can hold the popup. Storybook has a Density toolbar.
- b8d937d: Docs: Menu, Sidebar and Stepper pages in the three-tab format (Overview, Specs, Guidelines). Menu gains `isModal` (default `true`) and `container`, passed to Base UI: `isModal={false}` leaves the page scrollable and clickable while the menu is open, and `container` renders the popup somewhere other than `<body>`, such as an element in fullscreen.
- d1f0827: Add the Feed pattern (`npx shadcn add .../r/feed.json`): a list of events, each a sentence of who did what and when, with an avatar or icon, an optional comment under it, a connecting line (`hasConnector`), an empty state and an optional comment box (`composer`). **Breaking for copied templates:** the Projects, Project Detail and Home templates now render their activity on it: if you copied them, add `feed` and copy `ProjectActivity.tsx`, `Projects.tsx`, `Projects.module.css`, `ProjectDetail.tsx`, `ProjectDetail.module.css`, `Home.tsx` and `Home.module.css` again, and delete `ProjectActivity.module.css`. A status change's note now shows in a bordered comment box instead of an italic quote.

  Button and ToggleButton `md`: the icon is 20px (new `--icon-lg`) instead of 16px; the button stays 32px tall.

- a4f72c4: NavSidebar is laid out as in the Claude apps, and icons are drawn at weight 600.

  - **`NavSidebarButton`** (new export): a row that looks like an item, a button that can trigger a Menu or Popover. `appearance`: `ghost` (notifications with a `badge`, help, the account), `switcher` (a tenant switcher: medium weight, chevron right after the name, square avatar) or `field` (a search button drawn as an input). - 2685b1a: Breaking: the semantic token `--surface-subtle` is renamed `--surface-filled`. Same values (gray-50 in light, gray-800 in dark), same contrast guarantee for `--muted-foreground` on it. Find and replace `--surface-subtle` with `--surface-filled` in your CSS; the old name is no longer emitted in `tokens.css`.
- c09b45a: Body type: `--text-body-sm` is 12px on a 16px line (was 13 / 16) and `--text-body-xs` is 11px on a 16px line (was 10 / 14). Every body line height is now a multiple of 4px at 100% scaling. Token names are unchanged, so no code change is needed, but every small control label (Button, fields, Tabs, Tag and the other `sm` sizes), Menu shortcuts, Tooltip, captions and Badge counts render one pixel smaller or larger. If you relied on the old sizes, override the two tokens.
- d8eeb0e: Size tiers: every control now takes its height, inline padding, icon-to-label gap, icon and corner from one tier (`xs` 20px, `sm` 24px, `md` 32px). New tokens: `--control-xs`, `--control-{xs,sm,md}-pad`, `-pad-spacious`, `-gap`, `-radius` and `-radius-field`. See Foundations/Sizing.
  
  Radius steps (`--radius-sm` … `--radius-xl`, and the intents built on them) are now multiplied by `--scaling`, like padding, so corners shrink and grow with the rest of a scaled Theme. The `small` radius preset is 0.75 of the default (was 0.5).
  
  Visual changes, no API changes:
  - Small Button, ToggleButton and fields (TextInput, Search, Select, Combobox, NumberInput, DatePicker, Textarea): 6px between icon and label (was 8px); field icons are 14px (was 16px), the same as a small Button's.
  - Small Select draws its value at the small text size (it inherited 14px).
  - Tabs: small tabs take 8px padding, 14px icons and the small corner; pills chips are their track's corner minus the 2px inset.
  - Pagination: chevrons follow the tier icon (16px, 14px small) and previous/next stay square; small controls take the small corner.
  - Menu: items take 10px padding (was 8px) and a 4px corner nested in the popup (was 6px).
  - Tag: `md` takes 14px icons (was 16px), a 6px gap (was 4px) and the small corner; `sm` takes the small corner.
  
  If you override any of these sizes, override the tier token rather than the component.
- 38a358d: Stylelint at error level: spacing, radius, type, z-index, duration and outline properties take tokens, not literals. Exceptions carry a reason. Calendar's today disc uses `--radius-pill`; Breadcrumbs separators inherit font size.
- 738c750: Table: rows can expand. Pass `expandedContent={(row) => …}` and each row that returns content gets an expand button (after the checkbox column, named "Expand <row header>", with `aria-expanded` and `aria-controls`); the content opens under the row in one cell spanning every column. Rows that return `null`, `undefined` or `false` get no button. Expansion is uncontrolled with `defaultExpandedIds`, or controlled with `expandedIds` and `onExpandedChange`, like selection. Ids come from `getRowId`, so sorting keeps the right rows open. Opt-in: tables without `expandedContent` render as before.
  
  Also: when the row header is not plain text, a row's checkbox falls back to "Select row N" counted from `rows`, so sorting no longer renames it.
  
  Selected rows' dividers now take a tint of the selection colour. In light mode `--border` was as light as `--primary-subtle`, so the line between two selected rows disappeared.
